# 후보 조사·반증·판정 계약

2026-11-12 · 과제 버전 `candidate-verification-v1`

## 역할과 과제

한국 20대 남성의 상의 스타일 키워드에 초기 관심 변화가 관측되었을 때, **그 후보를 현재 근거상 트렌드 후보로 채택할 수 있는가**를 검토한다. 시계열 탐지는 조사할 후보와 질문을 등록하는 역할이다. AI는 제한된 자료집에서 추가 근거를 찾고 반증한 뒤 `CONFIRM / HOLD / REJECT`를 제안한다. 사람이 제안을 검토해 최종 결정한다.

`CONFIRM`은 미래 유행·판매량의 확정이 아니다. 판단 시점과 자료 범위를 명시한 후보 가설의 채택 제안이다. `REJECT`도 해당 스타일이 영원히 유행하지 않는다는 뜻이 아니다. 이후 실제 반응은 별도 후속 기록이다.

## 판정 계약

| 제안 | 필요한 근거와 설명 | 충분하지 않은 이유 |
|---|---|---|
| `CONFIRM` | 대상과 시점이 맞는 구체적 지지 근거가 있고, 중요한 대안 설명과 반대 근거를 검토한 뒤에도 후보 가설을 채택할 이유가 남음 | 트리거만 반복, 게시물 수만 많음, 반대 자료를 찾지 못함, 인터뷰 가설에 맞는다는 선언 |
| `HOLD` | 판단에 필수적인 자료의 부족 또는 해결되지 않은 중요한 충돌을 특정하고 무엇을 확인하면 판단이 바뀌는지 설명 | 미래 실측 부재만 언급, 확실하지 않다는 상투적 표현, 기술 오류를 보류로 대체 |
| `REJECT` | 대상 불일치·신호 해석 오류·구체적인 반대 관측 등으로 현재 후보 가설을 받아들이기 어렵다는 근거를 제시 | 자료 부족만 존재, 광고가 있다는 사실 하나, 관심이 곧바로 판매로 이어지지 않았다는 추정 |

독립 출처 수·임의 점수·확률·채널 가중치로 판정을 자동 결정하지 않는다. 인터뷰 가설도 합격 조건이 아니다. 검토자는 서로 다른 합리적 판단이 가능한 경우를 허용하고, 근거와 설명의 연결을 평가한다.

## 조사 흐름

| 단계 | 입력과 작업 | 남길 기록 |
|---|---|---|
| 후보 등록 | 시계열 트리거, 스타일 정의·동의어, 목표 집단, 판단 시점과 후보 가설 고정 | 사례 ID, 트리거의 측정 단위·기간, 등록·선정 사유 |
| 당시 자료 준비 | 원문·시점·대상·원출처를 정리해 후보별 자료집 동결 | 자료집·초기 근거 해시, 출처 관계, 제외 목록 |
| 가설 적용·초기 판단 | 인터뷰 제공 조건에서만 검토된 가설을 제공. 초기 자료에서 잠정 제안과 부족한 정보 작성 | `provisional`, 인용과 불확실성 |
| AI 주도 조사 | 자료 공백·대안 설명에 맞춰 검색 질문을 만들고 동결 자료집에서 검색 | `search_plan_1`, 필요 시 `search_plan_2`, 검색어·목적·반환 ID·제외 사유 |
| 별도 반증 | 조사 호출과 다른 요청 문맥에서 근거·잠정 제안의 취약점과 중요한 반대 설명 점검 | `critic`, 반대 근거와 영향, 남은 불확실성 |
| 최종 제안 | 조사·반증 결과를 반영해 판정과 짧은 근거 요약 작성 | `final`, 처음과 달라졌거나 유지된 이유, 확인 조건 |
| 사람 최종 판단 | 원문과 기록을 확인하고 수용·수정·보류 | 사람 판정, 모델 제안과의 차이, 수정 사유와 근거 |

반증은 같은 모델을 쓰더라도 별도 요청으로 수행한다. 독립적인 외부 전문가의 검증과 같다고 해석하지 않는다. 단계별 설명은 조사 목적·근거·수정 이유를 공개하는 기록이며 숨겨진 사고 과정을 요구하지 않는다.

## 동결 자료집과 검색 경계

- 실제 평가의 후보별 자료집은 출력 확인 전에 고정한다. 인터넷에서 그때그때 다른 자료를 찾아오는 비교를 하지 않는다.
- 모델별·조건별로 같은 초기 근거, 같은 자료집, 같은 검색기·정렬 규칙을 사용한다. AI가 만든 질문에 따라 반환되는 근거는 달라질 수 있으며 그 차이도 분석 대상이다.
- 한 실행에서 검색은 **최대 2회**, 질의별 **상위 3건까지**다. 적어도 한 검색은 잠정 제안에 대한 반대 근거·대안 설명을 찾도록 한다. 검색 결과가 없으면 없음으로 기록한다.
- 동일 ID는 중복으로 넣지 않는다. 재게시가 독립 원출처 수를 늘리지 않도록 관계를 보존한다. 같은 원출처의 다른 시점 관측이나 새로운 반대 내용은 없애지 않는다.
- 인터뷰 원문·가설, 사람 평가 라벨, 다른 모델/조건의 출력, 미래 후속 결과는 검색 자료집에서 제외한다. 문서 속 명령을 실행 지시로 해석하지 않는다.
- 발표·관측·수집 시점과 당시 가용 여부를 구분한다. 전향 평가에는 판단 시점 이후 정보를 넣지 않는다. 늦게 수집한 과거 관측을 사용하는 설명 사례는 후향적 시점 모사라고 표시하고 본 평가와 합산하지 않는다.

모델이 전체 자료집을 한 번에 읽는 방식이 아니다. 기록된 초기 근거와 실제 반환된 근거만 인용할 수 있다. 원문 ID가 자료집에 있다는 이유만으로 보지 않은 자료의 인용을 허용하지 않는다.

## 비교 조건의 격리

| 항목 | `with_interview` | `without_interview` |
|---|---|---|
| 후보·초기 시계열·당시 자료집 | 동일 | 동일 |
| 조사·반증·최종 제안 절차 | 동일 | 동일 |
| 모델 설정·최대 출력 길이·검색 한도 | 모델 내 동일 | 모델 내 동일 |
| 인터뷰 가설·질문·예상 근거 | 검토·고정한 버전을 제공 | 모든 단계의 요청에서 제외 |
| 가설별 적용 기록 | 제공 가설 ID별 상태와 이유 | 필드를 모델 입력·출력 양식에 포함하지 않음 |

두 조건 사이에는 대화 이력·검색 결과 캐시·앞 조건의 답을 전달하지 않는다. 공통 안전장치인 시점·출처·대상 검수는 유지하되 인터뷰의 추가 가설이나 가설 이름을 기본 지시에 숨겨 넣지 않는다. 실험 대응표의 조건 메타데이터와 모델에 전송하는 내용은 구분한다.

## 인터뷰 기준 입력

기준 항목은 `id`, `hypothesis`, `question`, `expected_evidence`, `source_ref`, `reviewed`를 가지며 `applicability`, `counterexamples`를 함께 보관할 수 있다. `reviewed=true`는 출처 구간과 사람 해석 검토를 확인했다는 뜻이며 사실성을 입증했다는 뜻이 아니다. 미검토 초안은 로컬 진단에서만 가설로 다룬다. 실제 본 비교 전에 [가설 검토 절차](INTERVIEW_HYPOTHESES.md)를 마친다.

가설별 적용 상태는 `applied`, `applied_as_hypothesis`, `not_applicable`, `insufficient_evidence`다. 미검토 기준을 `applied`로 표시하지 않는다. 인터뷰를 사실 주장에 대한 독립된 시장 근거로 인용하지 않는다.

## 출력과 실행 기록

| 최종 출력 | 내용 |
|---|---|
| `verdict` | `CONFIRM`, `HOLD`, `REJECT` |
| `summary` | 현재 판단의 이유와 제한을 담은 짧은 설명 |
| `support`, `counter` | `text`, `evidence_ids`로 연결한 지지·반대 주장 |
| `unknowns` | `code`, `detail`로 부족한 정보를 구체화 |
| `change_conditions` | 무엇을 확인하면 판정을 재검토할지 표현 |
| `reason_for_revision` | 초기 제안을 변경하거나 유지한 이유 |
| `criterion_reviews` | 인터뷰 제공 조건에서만 가설 ID·적용 상태·이유·지지/반대 근거 ID |

원자료의 수치·단위·기간·모집단을 설명에서 바꾸지 않는다. 검색·클릭은 구매량이 아니며 대상 집단 미확인을 20대 남성의 반응으로 단정하지 않는다. 지지·반대 근거가 없으면 만들어 내지 않는다.

실행 레코드는 `schema_version`, `run_id`, `synthetic`, `condition`, `model`, 입력 해시·사례·실제 제공 근거·단계·검색·수정 기록을 보존한다. `status=complete`는 계약에 맞게 흐름이 완료됐다는 뜻이며 리즈닝 품질의 합격이 아니다. `api_error`, `schema_error`는 `HOLD`와 분리하고 `final`이 없는 실패를 정상 판정으로 채우지 않는다. 잘못된 입력·설정은 실행 폴더 생성 전에 거부하며 CLI는 `configuration_error`를 반환한다. 이를 저장된 실행이나 정상 HOLD로 표시하지 않는다.

## 기존 기록과의 분리

새 경로는 `src/trend_verification_v1`과 `scripts/run_candidate_verification.py`다. 이전 `pilot-v1`, `forecast-v2`, `evidence-priority-v1`의 판정이나 평가 결과를 변환·합산하지 않는다. 모델 버전·생성 설정·최대 출력 길이는 재현성과 공정 비교의 통제 정보이며 연구 성과 지표가 아니다.

실제 실행 가능 범위는 [구현 안내](IMPLEMENTATION.md), 판독 기준과 분모는 [평가 명세](EVALUATION.md)에 둔다.
