# 인터뷰에서 추출한 검토 가설 10개

2026-11-12 · 추출 상태: **AI_selected_unreviewed** · 모든 항목 `reviewed=false`

사용자 제공 전사문 전체에서 트렌드 후보를 조사할 때 필요한 질문 10개를 AI가 추출했다. **사람의 원문 해석 검토가 끝났거나 가설이 입증되었다는 뜻이 아니다.** 발화자 구분과 자동 전사 정확성이 보장되지 않으므로 기업 담당자의 직접 발언이나 모집단 사실로 인용하지 않는다. 무관한 대화·개인 정보·비율 추정·임의 가격 기준은 제외했다.

[실행 입력 JSON](../../../data/interview/candidate-hypotheses-v1.json)에는 가설·질문·예상 근거·적용 조건·반례와 검토 상태가 들어 있다. [입력 사용 안내](../../../data/interview/README.md)에 실제 모델 동작 점검과 본 평가의 구분을 적었다. 이 가설 파일은 합성 데모의 기존 기준 파일과 별개다.

## 검토 가설과 확인 질문

| ID | 검토할 내용 | 당시 자료에 물을 질문 | 해석의 경계 |
|---|---|---|---|
| H1 | 목표 집단의 일치 | 관측한 연령·성별·시장 범위가 한국 20대 남성과 어떻게 겹치는가? | 전체 이용자 반응을 목표 집단의 직접 반응으로 확대하지 않음 |
| H2 | 관심과 실제 채택의 구분 | 검색·클릭·노출을 측정한 것인가, 구매·착용을 직접 관측한 것인가? | 검색을 구매량으로 바꾸지 않음. 관심 검토에 구매를 무조건 필수화하지 않음 |
| H3 | 미디어 노출과 독립 반응의 구분 | 원생산자·캠페인이 겹치는가? 홍보 밖의 새로운 반응이 있는가? | 재게시를 독립 반응으로 세지 않으며 홍보 자체로 기각하지 않음 |
| H4 | 계절과 생활 필요의 대안 설명 | 같은 시기의 과거 변화나 당시 날씨·착용 필요로 설명되는가? | 계절성과 새로운 스타일 변화가 함께 있을 수 있음 |
| H5 | 익숙함과 일상 착용 수용성 | 소개·화제에서 실제 일상 착용·반복 사용으로 이어진 직접 자료가 있는가? | 노출만으로 심리·수용성을 추정하지 않음 |
| H6 | 패션 관심 수준에 따른 반응 차이 | 선도 집단과 일반 이용자의 관심 수준·관측 범위를 직접 구분할 수 있는가? | 연령·성별과 관심 수준은 다른 축. 복장만 보고 집단을 분류하지 않음 |
| H7 | 가격 접근성과 관심의 괴리 | 당시 가격·대체 상품은 무엇이며 가격이 선택을 제한했다는 직접 근거가 있는가? | 고가라는 사실만으로 수요 부재나 구매 능력을 단정하지 않음 |
| H8 | 디자인과 품질의 선택 맥락 | 디자인·사용성·품질 중 무엇이 선택 이유인지 직접 확인되는가? | 연령별 선호의 고정 규칙이나 별도 상품 품질 평가로 확대하지 않음 |
| H9 | 브랜드 간 대체와 확산 경로 | 유사한 스타일 요소가 다른 브랜드·가격대에 언제 나타났는가? | 상품 공급의 반복과 이용자 채택을 구분하고 모방 관계를 단정하지 않음 |
| H10 | 상품을 넘어 반복되는 공통 스타일 요소 | 후보를 정의한 색·패턴·형태가 서로 다른 관측에서도 동일하게 확인되는가? | 단일 상품의 반응을 스타일 전체의 변화로 확대하지 않음 |

H1은 인구학적 범위, H6은 패션 관심 수준의 차이다. H2는 무엇을 측정했는지, H7은 관심과 선택이 다를 수 있는 가격 맥락을 묻는다. H3은 정보 원출처, H9는 상품 공급의 확산 경로, H10은 무엇을 같은 스타일로 묶을지 구분한다. H5는 일상 수용의 직접 관측, H8은 선택 속성의 근거를 확인한다. 같은 근거가 여러 가설에 관계되더라도 독립 관측을 늘려 세지 않는다.

## 실제 동작 점검에서 사용하는 방식

사용자가 요청한 실제 모델 동작 점검에는 이 파일을 사용할 수 있다. 다만 **AI가 추출한 미검토 가설을 전달하는 진단 실행**으로 기록한다. 모델은 각 항목을 `applied_as_hypothesis`, `not_applicable`, `insufficient_evidence`로 다루며 사람 검토가 끝난 기준처럼 `applied`로 표시하지 않는다. 실제 API가 응답했다는 사실과 가설의 타당성·모델의 성능을 구분한다.

10개를 모두 충족해야 확정하는 체크리스트가 아니다. 현재 후보 주장과 관련 없는 항목은 해당 없음, 관련은 있지만 직접 자료가 없는 항목은 자료 부족으로 남긴다. 개별 가설의 자료 부족만으로 전체 판정을 자동 HOLD하지 않는다. 반대로 부족한 정보를 지어내어 억지로 가설을 충족시키지도 않는다.

## 원문 추적과 사람 검토

공개 JSON의 `source_ref`는 `interview-map:iv1-H1` 같은 익명 매핑 키다. 비공개 `private/interview-source-map.json`이 원본 파일 해시, Unicode 문자 구간, 짧은 원문 발췌와 발췌 해시를 연결한다. 원문을 공개 저장소에 복사하지 않고도 권한 있는 검토자가 해석을 대조할 수 있게 한 것이다.

1. 검토자는 원문과 해시·구간을 대조하고 ASR 오류와 해석의 불확실성을 확인한다.
2. [인터뷰 해석 검토표](forms/WORKSHEETS.md#인터뷰-해석-검토)에 채택·수정·제외·미해결과 이유를 남긴다.
3. 확인한 항목만 새 버전에서 `reviewed=true`로 바꾸고 출처 참조·검토 이력을 함께 고정한다. **이는 해석 검토 완료이며 가설의 사실성 입증이 아니다.**
4. 실제 본 비교는 이 검토·동결 이후 별도의 새 후보와 사람 평가 기준표를 준비해 진행한다. 진단 결과를 본 뒤 유리하게 바꾼 가설은 새 개발 버전으로 분리한다.

## 비교군 격리

`with_interview`에만 가설을 제공한다. `without_interview`의 모든 단계에는 가설 내용·ID·적용 양식·다른 조건의 출력이 들어가지 않는다. 전사문과 가설을 검색 자료집에도 넣지 않는다. 공통 대상·시점·출처 검수와 조사·반증 절차는 두 조건에서 유지한다. 평가자는 인터뷰 가설 자체에 대한 동의를 정답으로 삼지 않는다.
