# 1차 예측 스펙과 실행 설정 기록

2026-11-08 · 현재 과제 지시 `forecast-v2` · v1 재현 기록 보존

**이번 주 확정 범위는 연구 환경, 예측·HOLD 기준, 입출력 형식과 Qwen 8건의 동작 확인이다.** 정식 연구 질문, 본 비교, 성능 판단, 논문 방향과 일정은 이후 결정한다.

첫 실행(v1)의 Qwen은 보류 7건에서 미래 확인값 부재를 이유로 들었다. [실제 프롬프트·출력 진단](QWEN_PROMPT_DIAGNOSIS.md)을 바탕으로 예측과 사후 확인, 보류 허용 조건을 구분한 v2 지시를 고정했다. 형식 검증 통과를 의도한 예측 수행의 성공으로 간주하지 않는다.

## 현재 1차 스펙 — v2

상세 규칙은 [FORECAST_V2.md](FORECAST_V2.md), 실제 고정 프롬프트는 [forecast-v2-prompt.json](forecast-v2-prompt.json)에 있다.

| 항목 | 이번에 정한 내용 |
|---|---|
| 과제 | 판단 시점까지의 과거 순위로 이후 7개 관측일의 상승 지속성을 예측한다. |
| HOLD | 필요한 과거 자료의 부재·손상·모순, 또는 과거 근거를 대조해도 방향을 정하기 어려운 경우에 구체적인 이유와 함께 허용한다. |
| HOLD로 처리하지 않을 이유 | 미래 정답이나 100% 확신이 없다는 사실, 이번 범위 밖인 광고·리뷰 정보의 부재만으로 보류하지 않는다. |
| 문턱과 관측 | 판정 문턱은 평가 기준이며 미래 관측값이 아니다. 목록 부재의 101도 계산 경계값이다. |
| 입출력 | 기존 상품 정보·과거 14개 관측·계산 특징·근거 ID를 유지한다. 출력도 verdict·summary·support·against·unknowns를 유지한다. |
| 이번 실행 | 같은 맨투맨 8건에 Qwen만 1회씩 요청한다. 사용자 입력과 모델 설정은 그대로 두고 시스템 지시만 교체한다. 재시도는 하지 않는다. |
| 확인할 행동 | 미래값을 요구하며 멈추는지, 문턱을 미래값으로 쓰는지, 예측 또는 허용된 HOLD를 실제 과거 근거로 설명하는지 확인한다. |

WATCH 증가나 HOLD 감소 자체를 성공으로 보지 않는다. 정답률 재채점과 모델 우열 판단도 이번 범위에 넣지 않는다. 이미 정답을 확인한 개발 자료이므로 독립 평가가 아니다. v1 원본은 보존하고 v2 요청·출력·비용은 별도 기록한다. v2 세션 상한과 누적 예산 계산은 [현재 실행 규칙](FORECAST_V2.md#예산과-실행-통제)에 명시했다.

## 아래 내용의 상태 — v1 재현 기록과 미확정 연구 후보

이하 자료·정답·모델·집계·봉인 규칙은 첫 실행 v1을 재현하기 위해 남긴 기록이다. 기준 자료 커밋은 `6fc299003000`이다. 연구 질문과 전체 비교 설계를 이번에 확정했다는 뜻은 아니다.

## 연구 질문 후보 — 미확정

급상승한 패션 상품의 순위가 이후에도 유지되는지 판단할 때 시계열 근거가 LLM에 주는 효과는 연구 방향 후보이다. 맨투맨을 개발 자료로 사용했으며 상의 자료 확장은 검토 후보로 남긴다.

- **RQ1:** 정적 상태에 과거 순위를 추가하면 판단이 개선되는가?
- **RQ2:** 동일한 과거 순위에 코드로 계산한 특징을 추가하면 판단과 수치 해석이 개선되는가?
- **RQ3:** Claude와 Qwen에서 효과의 방향, 오류, 실행 비용이 어떻게 다른가?

실제 판매량·광고 여부·시장 전체 유행을 정답으로 삼지 않는다. 관측 가능한 순위 지속성은 이번 테스트에 사용한 대리 지표다. 인터뷰 원문을 직접 검증한 연구로 표현하지 않으며, 현재 제공된 회의 기록과 프로젝트 문제 정의에 근거한다. 별도 학습, 사이트 수정, 신규 수집, 사용자 리뷰 기능은 이번 실행 범위 밖이다.

## 자료와 정답

기준 구간 7개 관측일 평균 순위를 R_B, 감지 구간 7개 관측일 평균을 R_D, 후속 확인 구간 7개 관측일 평균을 R_H라고 한다.

- 후보: `R_B - R_D >= 10`.
- 지속(PERSIST): `R_B - R_H >= 0.5 * (R_B - R_D)`.
- 소멸(FADE): 위 지속 조건을 충족하지 않음.
- 모델 판정: `WATCH`=지속 예측, `NOT_SUPPORTED`=소멸 예측, `HOLD`=기권.
- 예: 80위에서 40위로 상승했다면 후속 평균 60위 이내가 지속이다.

**7일은 달력상 7일이 아니라 수집이 있었던 7개 날짜다.** 원본 벤치마크의 표현은 변경하지 않고 연구용 입력과 보고서에서 이 의미를 명시한다. 확인 구간은 모델에 제공하지 않는다.

수집된 TOP100 목록에서 상품이 없으면 기존 규칙의 경계 대입값 101을 사용한다. 이는 실제 101위 관측이 아니다. 수집 자체가 없는 날을 상품의 목록 이탈로 바꾸지 않는다. 수집 목록의 완전성 한계도 남긴다.

모든 파일의 `historical_available_at`이 null이므로, 현재 확보한 과거 자료로 시점을 모사한 실험이다. 당시 가용 데이터 버전을 완전히 재현했다고 주장하지 않는다.

## 구현된 입력 분리와 비교군 후보

| 구분 | 허용 입력 / 방법 | 해석 |
|---|---|---|
| 고정 기준선 | 전부 지속, 전부 소멸을 각각 실행 | 테스트 정답을 보고 좋은 쪽을 고르지 않음 |
| 시계열 기준선 | 마지막 순위 또는 최근 3개 순위 평균이 확인 구간에도 유지된다고 예측 | 동일한 절반 유지 기준으로 판정 |
| A `static` | 상품 식별·현재 순위·공통 질문 | 과거 순위와 계산 특징 없음 |
| B `history` | A + 판단 이전 14개 관측일 순위 | B-A는 과거 흐름 제공 효과 |
| C `structured` | B + 같은 순위에서 계산한 기준/감지 평균·상승폭·관측 범위 | C-B는 계산된 근거 제공 효과 |

A/B/C 입력 생성은 구현했으며 실제 호출은 C에만 수행했다. A/B/C 전체 비교를 정식 연구로 수행할지는 이후 결정한다. 현재 구현은 모델별 동일 질문, 시스템 지시, 출력 구조를 사용하며, 비교군에 맞는 근거만 명시적으로 선택한다. 원본 features 전체나 rank_change 문장을 그대로 붙이지 않는다. 리뷰·할인·검색의 변화량과 계절성 지표는 제외했다. B와 C의 원시 순위는 같아야 한다. 근거 구성 차이를 서로 다른 자료량·다른 사건 효과와 혼동하지 않는다.

Claude는 `claude-sonnet-5-5`, effort `low`, temperature 미지정이다. A40는 `Qwen/Qwen3-8B`, BF16, thinking 활성화, temperature 0.6이다. 최대 출력 8,192토큰, 요청 제한시간 300초, 동시 요청 1개로 시작한다. 실행 시 실제 모델 ID·revision·서버 버전·설정을 남긴다. 서로 다른 모델의 추론 예산이 동일하다고 주장하지 않는다.

최종 출력은 verdict, summary, support/against의 text와 evidence_ids, unknowns다. 내부 추론 전문을 평가 정답으로 삼지 않는다. JSON 오류·존재하지 않는 근거 인용·응답 중단은 실패이며 HOLD로 치환하지 않는다.

## 구현된 집계 지표와 해석 후보

| 지표 | 분모와 정의 |
|---|---|
| 답변율 | 지속 또는 소멸로 답한 수 / 전체 N |
| 답한 사례 정확도 | 정답 수 / 답한 수 |
| 전체 처리 결과 | 정답·오답·HOLD·기술 실패 각각 / N |
| 지속 적중률 | 실제 지속인 지속 예측 수 / 지속 예측 수 |
| 지속 재현율 | 실제 지속인 지속 예측 수 / 실제 지속 수; HOLD와 실패도 분모에 포함 |
| 혼동 표 | 실제 지속/소멸 × 예측 지속/소멸/HOLD; 실패 수 별도 표시 |
| 근거 연결 | 유효 근거 ID, 출력 형식, 검토가 필요한 수치 오류; ID 일치가 의미적 정확성을 보장하지 않음 |
| 실행 비용 | 모델별 사례 시간·토큰·API 비용, 별도의 A40 총 임대 시간/비용 |

분모가 0인 지표는 0%가 아니라 계산 불가로 표시한다. 실패·미실행·보류를 별도 기록한다. 테스트 부분집합의 다수 비율은 사후 난이도 설명이고 학습된 예측기의 성능이 아니다.

정식 비교를 채택한다면 같은 사례의 정답·오답·보류를 함께 보는 방식이 해석 후보가 될 수 있다. 아직 개선 판단 규칙이나 본 평가 계획을 확정하지 않았다. 현재 한 시점에서 얻은 수치로 시간 일반화를 주장하지 않는다. 순위화된 확신도가 없으므로 risk-coverage 곡선/AURC나 보정된 확률을 제시하지 않는다. 반복 호출을 독립 표본 수 증가로 세지 않는다.

## 수행한 테스트의 실행·정보 봉인 규칙

1. 모의 응답으로 입력 분리, 검증, 저장, 비용 상한을 검사한다.
2. 실제 호출은 C × 8상품 × 2모델 = 16회로 한정한다. 복구 시도는 최대 4회, 총 20회이며 자동 반복 호출은 없다.
3. 각 응답과 실패를 즉시 저장한다. 동일 입력·모델·설정의 완료 결과는 재사용한다.
4. 예측과 기준선 결과를 해시로 고정한 뒤 정답을 복원한다. `benchmark/labels.digest.txt`의 봉인 해시와 일치해야 채점한다.
5. 수치는 저장·검증·채점 경로의 확인 기록으로 보존한다. Qwen의 과제 해석 문제가 확인된 상태에서 모델 우열이나 연구 효과의 결론을 내리지 않는다. A/B는 실제로 호출하지 않았다.

추가 비용 상한은 총 $5, Claude $2, A40 활성 시간 2시간이다. 요청 전 최대 예상 비용과 누적 사용을 확인한다. 사용량을 알 수 없는 실패는 보수적으로 예약 비용을 소비한 것으로 계산한다. GPU는 작업 후 중지하고 Global volume 보관료가 별도로 계속될 수 있음을 기록한다. 이번 작업에서 본 비교 예산을 추가하지 않는다.
