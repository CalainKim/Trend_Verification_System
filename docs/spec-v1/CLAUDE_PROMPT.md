# Claude 작업 프롬프트 · 트렌드 탐지 MVP

아래 내용을 저장소를 읽을 수 있는 Claude 코딩 세션에 전달한다. 먼저 SPEC.md를 기준으로 작업하며, 이전 검증·모델 비교 설계로 범위를 넓히지 않는다.

~~~text
너는 이 저장소의 패션 트렌드 탐지 1차 MVP를 정리하는 개발자다.

목표
저장된 실제 자료에서 여러 상품·브랜드에 걸쳐 상승하는 스타일 유형을 찾고,
후보로 선정한 이유와 주별 변화를 기존 Trend Monitor에서 확인할 수 있게 한다.

먼저 읽기
- docs/spec-v1/README.md
- docs/spec-v1/SPEC.md
- docs/spec-v1/ARCHITECTURE.md
- docs/spec-v1/LOCAL_RUNBOOK.md
- docs/spec-v1/SOURCES.md

설명 순서
1. 트렌드 탐지의 실제 업무 상황
2. 그 상황을 해결하기 위한 관측 가능한 방법
3. 기능과 현재 코드의 연결
4. 실행 결과로 확인한 해결 범위와 남는 한계

범위
- 수집/스냅샷, 상품명 속성·유형 연결, 상승·브랜드 분산, 다주 변화, 후보 표시.
- 기존 src/trend_pipeline, scripts/export_frontend.py, track_types.py와 화면 재사용.
- 기본 시연은 29CM 남성·여성 상의 각 TOP100의 저장 자료.
- 기본 화면의 검색 추이는 Google Trends만 연결돼 있다.
- NAVER 수집 코드·자료 보유와 화면 연결을 구분한다.
- 다른 팀 과제, 이전 쇼핑몰, 리뷰 폼, 다중 모델 비교, 학습,
  상품 추천·매입 자동화·미래 판매 예측을 추가하지 않는다.
- 기존 별도 검증 코드를 삭제하거나 새 필수 의존성으로 만들지 않는다.

사실 처리
- 제공된 해설·주간보고를 인터뷰 원문이나 기업 승인 기준으로 바꾸지 않는다.
- 원 전사문이 들어오면 트렌드 탐지 팀의 문답만 발언 위치와 연결한다.
- 의류 성별 분류를 구매자 성별/연령으로 간주하지 않는다.
- 점수는 관측 요약이다. 확률·검증된 예측 성능이라고 표현하지 않는다.
- 브랜드 집중이나 할인은 광고를 확정하는 근거가 아니다.
- 임계값은 현재 구현 규칙이며 인터뷰에서 합의한 값이라고 쓰지 않는다.
- 미매칭/누락/오래된 자료를 숨기지 않는다.

작업
1. 최신 코드와 스펙이 맞는지 확인하고 필요한 차이만 수정한다.
2. 저장 스냅샷으로 DB와 후보 목록을 새 출력 경로에 재생성한다.
3. 날짜·상품 수·상승 수·브랜드 분산·주별 방향을 확인한다.
4. 기존 화면에서 후보와 관련 상품을 읽을 수 있게 한다.
5. 변경에 맞는 테스트와 문서/그림의 일치를 확인한다.
6. draw.io 원본 수정 시 SVG·PNG도 같은 버전으로 내보낸다.

결과 보고
- 바뀐 동작과 파일
- 실행 명령과 확인된 수치
- 이 MVP가 해결한 부분 / 아직 확인하지 못한 부분
- 어떤 자료나 기능을 이번 범위에 새로 요구하지 않았는지
키, 개인 인터뷰 원문, 사내 데이터는 커밋하지 않는다.
~~~
