# 근거 해석과 판정의 평가 명세

2026-11-11 · `evidence-priority-v1` · 상태: 평가 설계와 빈 양식 준비, 새 과제 측정값 없음

## 평가 대상과 비교 단위

평가 단위는 **고정된 스타일 후보·판단 시점·근거 묶음 한 건**이다. 같은 사례의 `direct`와 `structured`를 Claude, Qwen 각각에서 비교한다. 모델 간 비교는 보조 분석으로 둔다. 향후 실제 확산 여부, 판매량, 모델 내부 사고 과정은 이 평가의 정답이 아니다.

두 방법에는 같은 근거와 출력 형식을 제공한다. 입력 해시, 모델 버전, 설정, 최대 출력 길이, 요청·응답·오류를 기록한다. 작성·실행 시각은 자료 시점과 재현 순서를 확인하는 기록으로 사용한다. 기존 맨투맨 8상품 결과는 이 평가에 합산하지 않는다. 헨리넥·럭비티·링거티의 과거 자료는 설명·개발용이며 본 평가 표본으로 재사용하지 않는다.

본 평가의 후보 목록·제외 규칙·표본 수·판단 시점·실행 설정은 새 출력 확인 전에 고정해야 한다. 현재 문서 작업에서는 본 평가 모집과 호출을 수행하지 않았다. 실험 결과가 있는 것처럼 빈 결과표를 채우지 않는다.

## 두 명의 독립 평가 절차

1. **근거 동결:** 원문과 범위·시점·출처 관계를 확인하고 근거 묶음 및 해시를 고정한다.
2. **기준표 작성:** 응도와 도은이 모델 출력을 보기 전에 사실, 중요 반대 근거, 미확인 정보를 각자 작성한다. 중요 반대 근거는 ‘무시하면 판정이나 그 이유를 바꿀 수 있는 내용’으로 정의하고 근거 ID와 이유를 적는다.
3. **기준표 합의:** 두 최초 기준표를 보존한 채 별도 합의본을 만든다. 합의하지 못한 항목은 미해결로 표시하고 정답 항목으로 강제하지 않는다. 모델 답을 보고 기준표를 유리하게 고치지 않는다. 사후 오류 정정은 새 버전과 변경 사유로 남긴다.
4. **출력 가림:** 모델·방법·실행 순서를 제거한 임의 출력 ID를 발급한다. 대응표는 평가 자료 밖에 보관한다. 후보·근거·출력 내용은 검증에 필요하므로 유지한다. 문체로 모델을 추측할 수 있는 한계는 남는다.
5. **독립 판독:** 두 평가자가 모든 배정 출력을 각각 평가한다. summary를 포함한 모든 사실 주장을 원자적인 주장으로 나누고, 중복된 사실은 한 번만 센다. 최초 판정과 메모를 확정한 뒤 상대 평가를 확인한다.
6. **불일치와 합의:** 최초 평가자 일치도를 먼저 계산한다. 불일치 항목은 이유와 근거를 대조하고 별도 합의본을 기록한다. 합의가 안 된 항목은 미해결로 남기며 다수결처럼 자동 확정하지 않는다.

사실 주장 ID나 분할이 다르면, 최초 평가를 동결한 뒤 **원문 위치와 동일 명제**를 기준으로 대응표를 만든다. ID가 같다는 이유만으로 같은 항목으로 취급하지 않는다. 같은 원자 주장으로 일대일 대응되고 두 사람이 평가를 확정한 항목만 최초 일치도에 포함한다. 분할·병합 불일치와 미대응 항목은 수와 이유를 공개하고, 원래 값을 소급 분해하거나 합의 값으로 대체하지 않는다. 합의본의 주장 목록과 근거 충실도는 별도로 집계한다.

유효한 JSON만 사람 평가에 보여 주어 선택 편향을 만들지 않는다. 원문을 읽을 수 있는 구조 오류는 진단 판독이 가능하지만 유효 출력으로 승격하지 않는다. API 실패나 읽을 수 없는 잘림은 의미 평가 불가이며 기술 실패로 남긴다. 사람 평가는 **정답 예측률이 아니라 근거 해석의 평가**다.

## 판독 항목

| 항목 | 선택지와 기준 |
|---|---|
| 사실 주장 근거 | `supported` / `unsupported` / `contradicted` / `unverifiable`. 인용 ID가 존재하는 것과 실제 내용이 주장을 뒷받침하는 것을 구분한다. 평가 불충분은 별도 `not_reviewed`다. |
| 해석의 범위 | 자료에서 허용되는 제한적 해석인지, 구매·집단·확산·인과를 과하게 단정했는지 확인한다. 해석을 직접 관측 사실로 채점하지 않는다. |
| 논리적 연결 | 출력에 드러난 전제 → 해석 → 판정이 연결되는지 `coherent` / `invalid` / `unresolved` / `not_assessable`로 평가한다. 근거 없는 도약, 자기모순, 순환논증, 중요한 반대 근거의 영향 누락, 대상·시점 범위 이동을 구체적 위치와 함께 기록한다. 내부 사고 과정은 요구하지 않는다. |
| 중요 반대 근거 | 각 기준표 항목이 정확히 반영되었는지 `addressed` / `missed` / `misrepresented` / `not_reviewed`로 표시한다. 단순 이름 언급만으로 addressed가 되지 않는다. |
| 중대한 오류 | 수치·단위·시점·대상 혼동, 존재하지 않는 사실, 지지되지 않는 인과·구매 단정 중 판정 또는 주요 설명을 바꾸는 오류. 종류·출력 위치·근거를 기록한다. 경미한 문장 문제와 구분한다. |
| 판정 적절성 | `appropriate` / `inappropriate` / `unresolved` / `not_assessable`. 최종 우선순위가 평가자 개인 선택과 달라도 제시한 근거와 불확실성에 부합할 수 있다. |
| HOLD 적절성 | 필수 자료 부족이나 중요한 충돌을 구체적으로 짚고 확인 조건을 제시했는지 평가한다. 미래 실측 부재만을 이유로 한 HOLD는 inappropriate다. HOLD가 아니면 해당 없음이다. |
| 확인 조건 | 무엇을 관측하고 그에 따라 어떤 판단을 재검토할지 확인 가능하게 적었는지 평가한다. 실제로 추가 수집을 수행했는지와는 구분한다. |

`unverifiable`는 모델이 한 사실 주장을 제공 자료로 확인할 수 없다는 평가다. `not_reviewed`는 평가자가 아직 읽지 않았다는 상태다. 둘을 합치지 않는다.

논리적 연결의 `coherent`는 명시한 전제와 불확실성 범위 안에서 관찰 우선순위의 이유가 설명된 경우다. `invalid`는 판정에 영향을 주는 도약·모순 등을 특정한 경우, `unresolved`는 읽고 검토했지만 적절성 판단을 확정하지 못한 경우, `not_assessable`은 원문 부재·읽을 수 없는 잘림 등으로 평가 자체가 불가능한 경우다. 아직 읽지 않은 항목은 null과 미완료로 남긴다. 관찰 우선순위는 유일한 수학적 결론이 아니므로 평가자와 최종 선택이 다르다는 이유만으로 논리 오류로 표시하지 않는다.

## 수치와 분모

모든 수치는 모델 × 방법별로 보고한다. 비율에는 분자·분모를 함께 적고, 사례별 비율의 단순 평균 대신 아래에 정의한 합계 분모를 사용한다. 결과를 합산할 때 모델이나 사례 수 차이를 숨기지 않는다.

| 지표 | 정의와 보고 규칙 |
|---|---|
| 주장 근거 충실도 | `supported` 사실 주장 수 ÷ 판독 완료한 모든 사실 주장 수. unsupported·contradicted·unverifiable를 분모에 포함한다. 모델의 해석 문장 수, 사실 주장 수, 미판독 수도 함께 보고한다. |
| 반대 근거 반영률 | addressed 중요 반대 근거 수 ÷ 합의 기준표의 평가 가능한 중요 반대 근거 수. 중요 반대 근거가 0이면 해당 없음. 아직 판독하지 않은 항목이 있으면 전체 비율은 미완료로 표시한다. |
| 중대한 오류 발생률 | 중대한 오류가 1개 이상 확정된 사례 수 ÷ 전체 시도 사례 수. 의미 평가 미완료·불가 사례가 있으면 이 값은 **확인된 오류의 최소 비율**이다. 아래의 미확인 수와 범위를 함께 낸다. |
| 판정 적절성 | appropriate / inappropriate / unresolved / not_assessable 건수를 모두 보고한다. 적절 비율은 appropriate ÷ (appropriate + inappropriate)이며 평가가 확정된 사례에만 해당한다. 전체 중 평가 확정 비율을 병기한다. |
| 보류 적절성 | HOLD 중 appropriate / inappropriate / unresolved / not_assessable를 보고한다. HOLD가 없으면 해당 없음이다. |
| 처리 결과 | 유효 PRIORITIZE·DEPRIORITIZE·HOLD·기술 실패 건수 ÷ 전체 시도 사례 수. 기술 실패는 파싱/ID 오류, 잘림, API 오류를 별도로 표시한다. |
| 평가자 일치 | 동일 항목에 대해 두 사람이 평가 가능한 값을 각각 확정한 항목 중 같은 값의 비율. 주장·반대 근거·논리적 연결·중대한 오류·판정 적절성을 따로 보고하며 비교 가능한 항목 수와 제외 사유를 적는다. 판정 적절성의 교차표도 제공한다. |
| 논리적 연결 적절성 | coherent / invalid / unresolved / not_assessable 건수를 모두 보고한다. 적절 비율은 coherent ÷ (coherent + invalid)이며 전체 시도 N 중 논리 평가가 확정된 비율을 병기한다. 평가 미완료는 별도 집계한다. coherent + invalid가 0이면 적절 비율은 해당 없음이다. |

전체 시도 사례 수를 `N`, 중대한 오류 확정 사례 수를 `E`, 오류 유무를 확정하지 못한 사례 수를 `U`라 하면 `E/N`과 함께 미확인 `U` 및 가능한 비율 범위 `[E/N, (E+U)/N]`를 표시한다. 기술 실패를 ‘오류 없음’으로 넣지 않는다. 모든 사례의 오류 여부가 확인되면 범위는 하나의 값으로 줄어든다. `N=0`이면 모든 비율은 미측정이다.

계획했으나 호출하지 않은 사례는 `not_run`으로 별도 보고하고 시도 분모에 넣지 않는다. 계획 수·시도 수를 함께 공개해 선택적 실행을 숨기지 않는다. 실패 뒤 재시도 기록을 덮어쓰거나 성공한 시도만 골라 주 분석으로 삼지 않는다. 본 비교는 사례별 첫 시도를 기준으로 하며 복구 호출이 있다면 별도 진단으로 보고한다.

처리 상태가 invalid인 출력의 원문에 PRIORITIZE가 있어도 처리 결과에서는 기술 실패다. 원문 판독 결과는 별도 진단표로 보존한다. 전체 결과표가 미완료이면 합격률이나 단일 우승 모델을 발표하지 않는다.

## 비교 해석

같은 사례에서 두 방법의 오류 발생 변화, 반대 근거 반영 변화, 보류·기술 실패 변화를 짝지어 제시한다. 특정 지표만 좋아지고 다른 지표가 나빠지면 상충 관계로 보고한다. 주장 수를 줄여 충실도만 높이거나 HOLD를 늘려 어려운 사례를 피한 결과를 개선으로 단정하지 않는다.

현재 초안에는 임의의 종합 점수, 80% 합격선, 통계적으로 유의한 우위가 없다. 표본 규모와 선정·의존 구조가 정해지지 않은 상태에서 검정이나 일반화 주장을 사전 약속하지 않는다. 실무 의사결정의 개선도 별도 사용자 연구 없이 주장하지 않는다.

## 필수 검수 시나리오

아래는 다음 구현·실행 단계의 검수 명세다. 이번 문서 작업에서 모델이 통과한 시험 결과가 아니다. 합성 사례의 동작 확인과 실제 자료의 평가 수치는 분리한다.

| 시나리오 | 확인할 결과 |
|---|---|
| 판단 시점 이후 문서를 추가 | 모델 입력에서 제외되고 제외 사유가 감사 기록에 남는다. |
| 같은 원문 재게시를 여러 개 추가 | 독립 출처 수가 늘지 않는다. 새 정보가 없는 복제만으로 판정 강화의 근거를 만들지 않는다. |
| 같은 원출처의 다른 시점·반대 관측 추가 | 중복으로 버리지 않고 해당 관측을 근거 묶음에 보존한다. |
| 수치·단위·기간·대상 불일치 | 구조 검증 또는 사람 판독에서 구체적인 오류 위치를 찾는다. 일반적인 문장 유사도로 통과시키지 않는다. |
| 대상 범위가 미확인인 기사 | 직접 20대 남성 관측으로 표시하지 않는다. |
| 중요한 반대 근거 추가 | 설명에서 해당 근거와 영향을 다룬다. 판정이 무조건 뒤집혀야 한다고 요구하지 않는다. |
| 참인 수치를 인용하지만 결론이 그 수치에서 나오지 않음 | 사실 인용이 맞아도 논리적 연결은 invalid가 될 수 있다. 빠진 전제·근거 없는 도약을 기록한다. |
| 결론을 전제로 반복하거나 요약과 본문이 충돌 | 순환논증·자기모순을 원문 위치와 함께 표시한다. 설명 길이를 논리 품질로 대체하지 않는다. |
| 미래 실제 반응 없음 | 이 사실 하나만으로 HOLD를 선택하지 않는다. |
| 근거 부족·약한 긍정만 존재 | 사실을 만들어 PRIORITIZE하거나 근거 없이 DEPRIORITIZE하지 않고 구체적인 HOLD를 허용한다. |
| JSON 잘림·미등록 ID·API 오류 | 유효 HOLD와 분리해 기술 실패로 남긴다. |
| 예전 예측 결과를 새 저장소에 입력 | task_version 불일치를 탐지하고 자동 변환·합산하지 않는다. |

## 양식과 기록 원칙

[양식 사용 안내](forms/README.md)의 빈 JSON과 Markdown을 복사해 사용한다. 템플릿의 빈칸·null은 실제 평가가 아니다. 독립 평가, 합의, 모델 대응표, 미래 관측은 서로 다른 파일로 보관한다. 원문 수정 없이 추가 기록을 남기며 해시와 버전으로 연결한다.
