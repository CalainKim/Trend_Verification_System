# 20대 남성 상의 트렌드 후보의 검토를 위한 근거 기반 리즈닝

교수님 검토용 연구 초안 · 2026-11-11 · 과제 버전 `evidence-priority-v1`

## 초록

검색·콘텐츠에서 관심 변화가 발견되었다는 사실만으로 해당 스타일을 계속 관찰할 가치가 있는지 판단하기는 어렵다. 반복 홍보, 대상 집단의 불일치, 과거의 일시적 관심, 서로 충돌하는 관측을 함께 검토해야 하기 때문이다. 본 연구는 한국 20대 남성의 상의 스타일 키워드를 대상으로, 현재 확보한 근거를 검토하여 관찰 우선순위와 그 이유를 제시하는 LLM 기반 방법을 제안한다. 후보 등록과 근거 수집을 판단 단계에서 분리하고, 동일한 근거 묶음에서 기본 판정과 구조적인 지지·반증 검토를 비교하도록 설계한다. 평가는 근거에 의해 뒷받침되는 주장, 중요한 반대 근거의 반영, 수치·시점·대상 오류, 전제에서 판정으로 이어지는 논리적 연결, 판정 및 보류 사유로 구성한다. 두 평가자가 모델 출력을 보기 전에 근거 기준표를 작성하고, 모델명과 비교군 이름을 가린 출력을 독립적으로 검토한다. 현재 완료한 작업은 연구 범위와 평가 설계의 확정 및 기존 실행 환경의 점검이다. 새 과제의 성능 결과는 아직 측정하지 않았으며, 기존 8상품 실험은 지시 수행과 출력 검증의 공학적 점검으로만 제시한다.

**핵심어:** 트렌드 후보 검토, 근거 기반 생성, 반증 검토, 관찰 우선순위, 보류 판단

## 1. 문제 정의

패션 트렌드 검토자는 검색량이나 언급량의 변화에서 후보를 발견한 뒤, 어떤 후보의 자료를 더 모으고 계속 관찰할지 결정해야 한다. 본 연구에서 해결할 문제는 후보를 발견하는 것과 그 후보를 뒷받침하는 근거를 평가하는 것이 서로 다른 작업이라는 데서 출발한다. 이 문제 정의는 프로젝트의 확정된 작업 가설이다. 확인하지 않은 인터뷰 원문을 직접 인용하거나, 특정 참여자가 동일한 문장으로 문제를 제기했다고 기술하지 않는다.

네이버·SNS의 변화 신호는 검토를 시작하게 하는 **트리거**다. 트리거가 발생했다는 사실을 미래 유행의 확정적 예측으로 해석하지 않는다. 리즈닝 단계는 후보의 정의, 판단 시점, 목표 집단을 기준으로 추가 자료와 과거 기록을 검토한다. 예를 들어 여러 게시물이 같은 캠페인에서 파생되었다면 독립적인 확산으로 중복 계산하지 않아야 하며, 상품 소개가 등장했다는 사실을 20대 남성의 구매 증가로 바꾸어 설명해서도 안 된다.

본 연구의 산출물은 **현재 근거로 계속 관찰할 구체적인 이유가 있는지, 어떤 반대 설명이 남는지, 무엇을 확인하면 판단이 달라지는지**를 제시하는 검토 카드다. 시장 전체의 유행 여부, 실제 판매 증가, 유행이 발생할 날짜를 정답으로 예측하는 과제와 구분한다. 미래 반응은 별도 관측 기록으로 남기며, 임의의 4주 기간에 반응이 없다는 이유로 이번 판정을 오답 처리하지 않는다.

초기 문서와 GitHub 인수인계 기록의 취지 대조는 [연구 범위 정합성 검토](ALIGNMENT.md)에 정리한다. 이번 연구는 그중 근거 추적성·반증 가능성·판단 일관성을 검증하는 첫 단계이며, 시장 트렌드 판별이라는 전체 제품 목표를 완료했다고 주장하지 않는다.

### 1.1 연구 질문

| 연구 질문 | 비교에서 확인할 내용 |
|---|---|
| RQ1. 구조적인 근거·반증 검토가 기본 판정보다 근거 오류와 과도한 결론을 줄이는가? | 같은 자료와 출력 형식에서 주장 지원 비율, 반대 근거 반영률, 논리적 연결 적절성, 중대한 오류 발생률 비교 |
| RQ2. 자료 부족과 충돌을 적절히 다루면서 과도한 보류를 피하는가? | 판정·보류 사유의 적절성과 전체 처리 결과를 함께 비교 |
| RQ3. 구조적 검토의 논리적 특성과 오류 유형은 서로 다른 모델에서도 관찰되는가? | 각 모델 내 방법 비교를 먼저 수행하고 Claude와 Qwen에서 공통·상이한 근거 해석과 논리 오류 유형을 분석 |

기여 후보는 이 적용 범위에 맞는 근거 관리 방식, 동일 자료 비교 설계, 사람이 재검토할 수 있는 판정·평가 기록이다. LLM과 시계열을 결합했다는 사실, GPU 종류, 설명의 길이 자체를 새로운 기여로 주장하지 않는다. 방법의 유용성은 본 평가 결과에 따라 판단한다.

## 2. 관련 연구

Gao 등의 ALCE는 근거를 검색하고 인용을 포함한 답변을 생성하는 시스템을 평가하며, 유창성·정확성·인용 품질을 구분한다. 이는 인용이 존재하는지와 인용이 주장을 실제로 뒷받침하는지를 나누어 볼 필요성을 뒷받침한다. 본 연구는 인용 ID의 기계적 검사와 사람의 주장 지원 평가를 분리한다. ALCE의 자동 평가 도구나 벤치마크 점수를 그대로 재현하는 설계는 아니다. [Gao et al., 2023](https://aclanthology.org/2023.emnlp-main.398/)

Turpin 등은 입력의 편향 요소가 답변에 영향을 주어도 설명에서 이를 드러내지 않는 사례를 보고했다. 따라서 그럴듯한 설명문이나 추론 모드 설정만으로 모델 내부 판단 과정의 충실성을 확인할 수는 없다. 본 연구에서 ‘리즈닝 검증’은 외부에서 확인 가능한 주장·근거 연결과 입력 변화에 대한 동작 점검을 뜻한다. 이 선행 연구의 결과를 현재 Qwen의 특정 오류 원인으로 단정하지 않는다. [Turpin et al., 2023](https://arxiv.org/abs/2305.04388)

Traub 등은 보류를 허용하는 선택적 분류에서 오류 위험과 답변 범위를 함께 평가하는 문제를 다루었다. 본 연구 역시 답한 사례의 품질만 제시하지 않고 보류와 기술 실패를 포함한 전체 처리 결과를 보고한다. 다만 현재 과제는 보정된 연속 신뢰도와 여러 보류 임계값을 제공하지 않으므로, 해당 연구의 다중 임계값 지표 AUGRC를 계산했다고 주장하지 않는다. [Traub et al., 2024](https://arxiv.org/abs/2407.01032)

이들 연구를 바탕으로 본 연구가 제안하는 구조적 검토는 출처 적합성·독립성·반대 설명을 명시적으로 확인하는 작업 절차다. 해당 절차가 패션 후보 검토에 효과적이라는 주장은 본 연구에서 검증할 가설로 남긴다.

## 3. 자료와 연구 단위

### 3.1 후보와 목표 집단

사례의 단위는 **스타일 키워드와 판단 시점의 조합**이다. 같은 스타일을 여러 날짜에 평가할 경우 서로 독립적인 표본으로 단순 합산하지 않는다. 같은 상품의 색상 변형이나 동의어 역시 별개의 스타일로 자동 분리하지 않는다.

사례 등록 시 후보 이름, 포함·제외할 의미, 동의어, 한국 시장과 20~29세 남성이라는 목표 집단, 판단 시점, 후보를 등록한 신호를 기록한다. 목표 집단과 관측 집단이 다르면 그 차이를 근거의 한계로 전달한다. 네이버 검색 API의 연령 코드 `3`과 `4`는 각각 19~24세와 25~29세이므로 합친 범위는 19~29세다. 이를 정확한 20~29세 집단으로 표시하지 않는다. [네이버 검색 API](https://developers.naver.com/docs/serviceapi/datalab/search/search.md)

네이버 검색 지수는 요청 구간에 대해 정규화된 상대값이며, 쇼핑인사이트는 검색 클릭 추이를 제공한다. 요청 조건이 다른 지수를 절대량처럼 비교하거나, 클릭·검색을 구매량으로 해석하지 않는다. 성별·연령이 없는 기사나 상품 자료는 보조 맥락으로 사용할 수 있지만 목표 집단의 직접 반응으로 승격하지 않는다. [검색 지수 정의](https://developers.naver.com/docs/serviceapi/datalab/search/search.md), [쇼핑인사이트 정의](https://developers.naver.com/docs/serviceapi/datalab/shopping/shopping.md)

### 3.2 현재 자료의 용도

| 자료 | 현재 사용할 용도 | 적용 범위의 제한 |
|---|---|---|
| 맨투맨 8상품·7브랜드의 기존 실행 | 환경 연결, 지시 수행, 근거 ID 검증 점검 | 상품 순위 과제이며 스타일 우선순위의 평가 표본이 아님 |
| 헨리넥·럭비티·링거티의 과거 네이버 기록 | 스타일 정의와 자료 구조를 설명하는 사례 | 결과를 알고 선정한 과거 사례로 독립 성능 평가에 사용하지 않음 |
| 기존 럭비티 파일럿 | 검색·쇼핑 자료의 연결 형식 확인 | 저장된 자료 범위와 목표 집단 조건을 개별 확인해야 함 |
| 합성 다채널 예제 | 미래 자료·반복 게시·대상 혼동 검사 | 실제 확산이나 모델 성능의 증거가 아님 |
| 새 본 평가 자료 | 같은 근거의 기본 판정과 구조적 검토 비교 | 별도 모집·고정 전이며 현재 표본 수와 결과는 미측정 |

3개 스타일의 기존 자료는 2025년 3~4월 네이버 기록을 나중에 조회한 설명 사례다. 기존 목록에 있는 무신사 편집·인터뷰 자료 4건의 발표일은 2025년 5~9월이므로, 4월 말 판단 시점을 모사하는 입력에는 포함할 수 없다. 이 자료를 근거 묶음의 예시로 사용할 때는 실제 시점과 용도를 함께 표시한다. 자료별 출처와 확인 상태는 [출처 기록](SOURCES.md)에 정리한다.

### 3.3 근거의 시점과 독립성

각 근거에는 원문 URL, 원생산자, 발표 시점, 실제 관측 구간, 수집 시점, 확인 가능한 가용 시점, 대상 집단, 지표의 단위와 집계 범위를 보존한다. 알 수 없는 값은 추정하여 채우지 않는다. 판단 이후의 정보를 모델 입력에 포함하지 않으며, 과거 기간을 나중에 수집한 자료는 후향적 설명 자료로 구분한다.

문서 수와 독립 출처 수는 별도로 기록한다. 같은 캠페인의 보도자료·재게시를 다른 URL이라는 이유만으로 독립적인 관심으로 세지 않는다. 반대로 같은 출처의 서로 다른 시점 관측이나 반대 증거는 남긴다. 독립 출처의 개수만으로 `PRIORITIZE`를 자동 결정하지 않는다.

## 4. 제안 방법

### 4.1 처리 흐름

처리는 후보 등록, 근거 수집·정제, 시점·대상·중복 확인, 근거 묶음 고정, LLM 검토, 우선순위 카드 작성, 사람 검토의 순서로 구성한다. 수집기는 근거를 모으고 코드는 확인 가능한 수치를 계산한다. 모델은 고정된 근거를 바탕으로 판단을 설명한다. 이번 비교는 근거 검색 성능과 모델 판단 성능이 섞이지 않도록 같은 사례의 근거를 두 방법·두 모델에 동일하게 제공한다.

### 4.2 판정과 출력

| 판정 | 의미 | 혼동하지 않을 내용 |
|---|---|---|
| `PRIORITIZE` | 현재 근거에서 계속 관찰할 구체적인 이유가 있고 주요 반대 근거를 고려해도 그 이유가 남음 | 유행·판매 증가의 확정 또는 발생 확률 |
| `DEPRIORITIZE` | 대상 불일치·반복 홍보·관측된 약화 등 구체적인 이유로 현재 우선순위를 낮춤 | 영구적 실패나 미래 확산 불가능 |
| `HOLD` | 중요한 자료 부족 또는 근거 충돌로 현재 우선순위를 정하기 어려움 | API 오류, 출력 파싱 실패, 미래 정답 부재 자체 |

출력은 판정, 짧은 요약, 지지·반대 주장과 해당 근거 ID, 부족한 정보, 판단을 바꿀 추가 확인 조건으로 구성한다. 광고가 있다는 사실만으로 우선순위를 낮추거나, 미래 실측이 없다는 이유만으로 보류하지 않는다. 광고·계절성·과거 재등장은 제공된 근거가 허용하는 범위에서 대안 설명으로 다룬다. 근거가 없는데 이를 사실로 생성하지 않는다.

관찰 우선순위는 자료와 시점에 조건부인 권고다. 수치화된 확산 확률이나 임의의 종합 점수를 출력하지 않는다. 사람의 최종 결정은 모델 권고와 구분하여 저장한다.

### 4.3 비교군과 실행 통제

| 비교군 | 공통 조건 | 다른 지시 |
|---|---|---|
| 기본 판정 | 동일 후보·근거·출력 형식 | 근거를 읽고 판정과 설명 작성 |
| 구조적 검토 | 동일 후보·근거·출력 형식 | 대상 적합성 → 출처 독립성 → 지지 근거 → 반대 설명 → 불확실성을 검토한 뒤 판정 |

같은 모델에서는 모델 버전, 생성 설정, 입력 자료 순서, 최대 출력 길이를 동일하게 유지하고 검토 지시만 바꾼다. Claude와 Qwen은 각각 내부의 두 방법을 먼저 비교한다. 모델 간 비교는 같은 검토 방법에서 나타나는 공통·상이한 논리 특성과 오류 유형을 살피는 보조 분석이며 모델 순위를 정하는 목적이 아니다. 근거 묶음 해시, 프롬프트 버전, 모델 설정, 원문 응답, 검증 결과를 기록해 절차를 재현할 수 있게 한다. 최대 출력 토큰은 비교 조건을 맞추는 설정값으로만 사용한다.

기존 `fixed/adaptive` 채널 가중치 비교는 이번 기본 판정/구조적 검토와 다른 실험이다. 기존 `forecast-v2` 상품 순위 예측 기록도 새 과제와 합산하지 않는다. 새 계약은 `evidence-priority-v1`로 분리하며, 현재 문서 단계에서 기존 실행기가 이미 이 계약을 지원한다고 표시하지 않는다.

## 5. 평가 설계

### 5.1 평가 기준표와 독립 검토

두 평가자는 모델 출력을 보기 전에 동일 근거 묶음에서 확인 가능한 사실, 중요한 반대 근거, 알려지지 않은 정보를 각각 표시한다. 각 항목은 원자료와 연결하고, 불일치를 조정한 기준표를 고정한다. 최초 기록도 보존한다. 기준표는 시장의 미래 정답이 아니라 주어진 자료를 읽는 기준이다.

출력 평가에서는 모델명과 비교군 이름을 가리고 순서를 섞는다. 두 평가자가 독립적으로 항목을 평가한 다음 불일치를 논의한다. 원래 평가와 합의 결과를 별도로 남긴다. 문체만으로 방법이 추측될 가능성은 남으므로 완전한 눈가림을 보장한다고 표현하지 않는다. Claude 출력이나 자동 심판의 판단을 사람 평가의 정답으로 대체하지 않는다.

사실 주장은 가능한 한 독립적으로 확인할 수 있는 단위로 나누어 검토한다. ‘검색 관심이 증가했다’와 ‘구매가 늘었다’가 한 문장에 있어도 별개로 확인한다. 사실 진술의 지원 여부와 그 사실에서 우선순위로 이어지는 설명의 적절성을 구분한다. 미래를 확정한 문장이 없는지, 반대 근거를 단순 나열한 뒤 결론에서 무시하지 않았는지도 평가한다. 특히 출력에 제시된 전제 → 해석 → 판정의 연결을 따라, 근거에 없는 도약, 자기모순, 결론을 전제로 되풀이하는 순환논증, 중요한 반대 근거의 영향 누락, 대상·시점 범위의 이동을 확인한다. 이는 공개된 짧은 설명의 논리적 정합성 평가이며 모델 내부 사고 과정의 복원이나 형식 논리의 완전한 증명이 아니다.

### 5.2 지표

모델·방법별 전체 시도 사례 수를 `N`이라 한다. 계획했으나 호출하지 않은 사례는 `not_run`으로 별도 보고하고 `N`에는 넣지 않으며, 계획 수와 시도 수를 함께 공개한다. 사례별 첫 시도를 주 분석으로 사용하고 실패 뒤 복구 호출로 원래 기록을 대체하지 않는다. 기술 실패나 형식 오류가 생긴 사례도 `N`에 남긴다. 내용 지표에서 평가할 수 없는 응답은 0점으로 위장하지 않고 미평가 사유와 건수를 별도 보고한다.

| 지표 | 정의 | 함께 제시할 값 |
|---|---|---|
| 주장 지원 비율 | 근거로 뒷받침되는 사실 주장 수 ÷ 검토한 사실 주장 수 | 주장·사례 수, 내용 미평가 사례 수 |
| 반대 근거 반영률 | 적절히 반영한 중요 반대 근거 수 ÷ 기준표의 중요 반대 근거 수 | 기준표 항목 수, 반대 근거가 없는 사례 수 |
| 중대한 오류 발생률 | 중대한 오류가 확인된 사례 수 ÷ `N` | 오류 유형, 내용 미평가 사례 수, 기술 실패율 |
| 판정·보류 적절성 | 현재 판정의 이유가 근거와 판정 정의에 맞는지 독립 평가 | 판정별 적절·부적절·미해결·평가 불가 건수 |
| 전체 처리 결과 | `PRIORITIZE`·`DEPRIORITIZE`·`HOLD`·기술 실패 건수 및 비율 | 항상 전체 사례를 분모로 사용 |
| 평가자 일치도 | 합의 전 동일하게 평가한 항목 수 ÷ 두 사람이 확정한 비교 가능한 항목 수 | 항목별 분모, 미해결·평가 불가 등 제외 사유, 판정 일치표 |
| 논리적 연결 적절성 | 출력의 전제·해석·판정이 모순·순환·근거 없는 도약 없이 연결되는지 평가 | 적절·부적절·미해결·평가 불가 건수, 오류 유형과 출력 위치 |

수치·단위·기간·대상 혼동, 없는 정보의 생성, 근거 범위를 넘는 단정 중 판정이나 핵심 설명을 바꿀 수 있는 오류를 중대한 오류로 분류한다. 합의되지 않은 경우에는 불일치를 남긴다. 중대한 오류 확정 사례를 `E`, 오류 여부 미확정 사례를 `U`라 하면 `E/N`은 확인된 오류의 최소 비율이며, `[E/N, (E+U)/N]` 범위와 미확인 수를 함께 제시한다. 기술 실패를 오류 없음으로 취급하지 않는다. 분모가 없으면 해당 없음으로, 아직 시도하지 않은 결과는 미측정으로 표시한다. 세부 집계는 [평가 명세](EVALUATION.md)를 따른다.

주장을 적게 쓰면 지원 비율이 높아질 수 있고, 보류가 많으면 답한 부분만 좋아 보일 수 있다. 따라서 반대 근거 반영, 처리 결과, 판정 적절성을 함께 비교한다. 임의의 가중 평균이나 ‘80% 이상’ 합격선은 사용하지 않는다. 우선 같은 사례의 두 방법에서 어떤 오류가 줄거나 늘었는지 짝지어 보여주고, 품질과 처리 범위가 엇갈리면 상충 관계로 보고한다.

### 5.3 진단 시나리오

본 평가와 별도로 미래 문서 추가, 재게시 추가, 대상 집단 불명확 자료, 잘못된 수치·단위, 중요한 반대 근거 추가, API 오류·잘린 JSON을 다루는 진단을 설계한다. 미래 문서는 필터에서 제외되어야 하고 재게시는 독립 출처 수를 늘리지 않아야 한다. 중요한 반대 근거를 추가했을 때는 그 근거를 설명에 반영하는지 확인한다. 반대 근거 한 건이 추가되었다는 이유만으로 반드시 판정이 뒤집혀야 한다는 규칙은 두지 않는다.

자동 검사는 허용된 ID와 원문 수치, 자료 시점, 상태 구분을 확인한다. 근거가 주장을 실제로 뒷받침하는지와 판단 사유의 적절성은 사람 평가 항목이다. 합성 진단 통과를 실제 스타일 자료에서의 성능으로 합산하지 않는다.

## 6. 현재 구현과 예비 점검

### 6.1 확보한 실행 기반

기존 작업에서 Claude API와 A40의 Qwen3-8B 연결, 같은 입력의 응답 저장, 버전별 프롬프트 기록, 출력 형식·근거 ID 검증을 확인했다. 기존 자료 수집과 근거 검색은 재사용 후보다. 새 우선순위 계약, 기본/구조적 비교, 두 사람의 평가 절차는 이번에 확정한 설계이며 새 과제의 종단 실행 및 본 평가가 완료된 상태는 아니다.

### 6.2 기존 Qwen 동작 기록

2026년 11월 8일 같은 맨투맨 8상품을 대상으로 예측·보류 지시를 명확히 한 프롬프트를 사용하여 Qwen만 8회 재실행했다. 이 자료는 이미 개발에 사용한 상품 자료다. [실행 및 실제 출력 점검 기록](../FORECAST_V2_RESULTS.md)

| 최소 과제 수행과 형식·근거 ID 검증 동시 충족 | 2/8건 | 새 스타일 과제의 합격률이 아님 |

## 7. 한계와 후속 연구

첫째, 평가자는 프로젝트 참여자 두 명이므로 도메인 판단과 기준표 구성에 편향이 있을 수 있다. 합의 전 기록을 보존하고, 외부 전문가 평가와의 일치는 별도 검증 과제로 둔다. 현재 사람 평가가 실무 효용을 이미 입증한다고 표현하지 않는다.

둘째, 현재 설명 사례는 결과를 알고 선정한 과거 자료이며 수집 시점도 판단 시점보다 늦다. 모델이 사전학습에서 해당 스타일의 후속 정보를 보았을 가능성도 배제할 수 없다. 새 본 평가에서는 후보를 결과와 모델 출력에 맞추어 교체하지 않고, 근거와 프롬프트를 먼저 고정해야 한다. 같은 스타일·원출처가 개발과 평가에 반복되는 의존성도 기록한다.

셋째, 네이버·커머스·콘텐츠 자료는 모집단과 관측 행위가 서로 다르다. 조회 조건이 확인된 집단의 검색 관심, 편집자의 상품 소개, 구매자의 행동을 하나의 지표로 합치지 않는다. 자료 접근 제한 때문에 확보하지 못한 채널은 부정적인 관측으로 처리하지 않는다.

넷째, 본 연구는 현재 자료에 조건부인 검토 품질을 평가한다. 나중의 실제 반응을 추적할 때는 우선 관찰뿐 아니라 보류·우선순위 낮춤 후보도 함께 기록한다. 아직 확산이 관측되지 않은 경우 관측 종료 시점과 자료 범위를 적고, 이를 영구적인 실패로 해석하지 않는다. 미래 예측의 정오를 주장하는 후속 연구를 수행한다면 사건 정의와 관측 기간을 그 실험 전에 별도로 정해야 한다.

## 8. 현재 결론

본 연구는 한국 20대 남성의 상의 스타일 후보를 대상으로, 현재 근거를 검토하여 관찰 우선순위와 반대 설명을 제시하는 과제를 정의했다. 같은 자료를 사용한 기본 판정과 구조적 검토, 두 사람의 독립 평가, 전체 처리 결과를 포함하는 평가 체계를 설계했다. 현재 확보된 실행 기록은 환경 연결과 모델 오류의 점검 결과다. 이번 연구의 중심은 근거 추적성, 반증 가능성, 설명과 판정의 논리적 정합성을 검증하는 방법론이다. 제안 방법이 기본 판정보다 우수한지에 대한 결론은 새 과제의 본 평가 이후에 제시한다.
