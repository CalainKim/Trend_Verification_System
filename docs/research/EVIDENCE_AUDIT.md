# 입력 근거와 최종 설명의 일치 여부 점검

이 문서는 **모델에 실제로 제공한 입력과 최종 설명이 맞는지** 점검한 기록이다. 확인 구간 정답, 정답 파일, 채점 결과를 열지 않고 작성했다. 따라서 아래 건수는 지속·소멸 예측의 정답률이 아니며, 잘못된 설명이 반드시 잘못된 최종 예측을 뜻하지도 않는다. 원래 출력·프롬프트·설정은 수정하지 않았다.

이번 주 목적은 연구 환경과 1차 구현·입출력 스펙 점검이다. 아래 내용은 출력 진단 기록이며 논문 결론이나 정식 평가 계획이 아니다. Qwen의 보류 7건에 대해서는 [실제 프롬프트·출력 원인 점검](QWEN_PROMPT_DIAGNOSIS.md)을 별도로 정리했다. 예측 지시와 보류 규칙의 경계가 충분했는지 확인하기 전에는 이 출력을 모델 능력 비교로 앞세우지 않는다.

## 점검 범위와 집계 방법

- 대상: `private/research-pilot/live/state.json`의 `structured` 입력·최종 출력. Claude 8건을 먼저 점검하고, 같은 프롬프트의 Qwen 8건 완료 후 추가 점검했다. 이 점검 담당은 두 모델 모두 정답과 채점 결과를 열람하지 않았다.
- 비교 자료: 각 출력에 대응하는 `prepared_input`의 원시 14개 순위, 계산 특징, 구간 정의, 목록 부재의 의미와 제한 사항. 저장된 `numeric_flags`도 함께 검토했다.
- **근거 문장 단위**: `support` 또는 `against` 배열의 객체 하나를 1건으로 센다. 한 객체에 여러 문장·숫자가 있어도 분모에서는 한 번만 센다. Claude는 지지 15건 + 반대 19건 = **34건**, Qwen은 지지 5건 + 반대 1건 = **6건**이다.
- 별도로 각 모델의 요약 8개씩, `unknowns` 항목 Claude 25개·Qwen 10개를 읽었다. 같은 오류가 요약에 반복되더라도 근거 객체 오류 수에 다시 더하지 않는다.
- 확인 항목: 숫자·날짜·구간 소속, 개수, 계산값과 비교 방향, 계산 경계값과 실제 관측의 구별, 주장에 포함된 수학적 필요조건, 입력에 없는 사실의 단정. 단순한 미래 전망·확률 표현은 정답 없이 참·거짓으로 분류하지 않는다.
- 이 기록은 자동 숫자 일치 검사와 별도로 수행한 **AI 보조 내용 점검**이다. 사람 평가자의 독립 판정·복수 평가자 합의가 아니며, 모든 사실 오류를 찾았다고 보장하지 않는다. 논문에서 사람 평가 결과로 표기하면 안 된다.

## 자동 플래그를 그대로 오류 수로 쓰면 안 되는 이유

63개 플래그에는 날짜 `10/11` 또는 조사와 붙은 날짜의 숫자, 목록 내 관측 수처럼 원시 값에서 셀 수 있는 숫자, 문장 끝 마침표·조사에 따른 숫자 추출 차이, 인용한 한 근거에 직접 쓰이지 않았지만 전체 입력에는 존재하는 정의가 섞여 있다. 예를 들어 `0.7143`은 입력과 출력에 모두 있는데도 여러 사례에서 경고가 남았다. `최소 개선폭 10` 역시 입력의 공통 정의에 있다.

반대로 T1의 33위와 T3의 11위는 전체 `rank_history`에 실제 존재하므로 단순 숫자 일치 검사만으로는 **잘못된 구간에 배치한 문제**를 찾기 어렵다. 따라서 자동 플래그는 검토 대상을 찾는 보조 신호로만 사용하고, 63을 수치 왜곡 건수로 보고하지 않는다. 현재 실험의 검사기와 출력은 그대로 보존하며, 향후 날짜·숫자 토큰화와 구간 귀속 검사를 개선할 때 별도 버전으로 기록한다.

### Q1: 확인 문턱을 미래 평균처럼 사용하고 반올림 근접으로 기준 충족을 단정

상품 **4125187 · `support[0]`**은 다음과 같이 설명했다.

> 이후 7개 관측일 평균 95.36위로, 101 - 95.36 = 5.64계단이 기준 상승분 절반(11.29/2=5.645)과 근접하여 지속 기준을 만족.

입력의 **95.36은 `confirmation_mean_rank_threshold`의 표시값**이다. 실제 미래 평균도 아니고, 자료에서 독립적으로 얻은 미래 평균 추정치도 아니다. 모델은 제공된 문턱을 미래 평균 자리에 대입해 자기충족적인 판단 근거로 사용했다. 미래 순위를 관측했다고 명시한 것은 아니지만, 해당 미래 평균을 단정할 입력 근거가 없다.

또한 `101−95.36=5.64`, `11.29÷2=5.645`라는 산술 자체는 맞지만 **5.64는 5.645보다 작다**. 둘이 가깝다는 사실만으로 `이상` 조건을 만족한다고 결론 내릴 수 없다. 원래 정의는 반올림 전 값으로 비교하도록 되어 있다. 이 사례는 단순 덧셈·뺄셈 오류보다는 **문턱의 의미와 비교 연산의 해석 오류**에 해당한다. 실제 확인 구간의 정답을 보고 판정한 내용은 아니다.

같은 사례의 `unknowns[0]`는 계산 전 소수 셋째 자리 값이 없다고 설명한다. 표시된 특징은 반올림되어 있지만 입력에는 원시 14개 관측값이 있으므로 과거 평균과 문턱을 다시 계산할 수 있다. 미래 평균이 없다는 문제와 과거 수치의 표시 정밀도 문제를 구분해야 한다.

### 미래 관측을 요구하며 보류하는 출력

HOLD 7건은 모두 요약 또는 부족한 정보에서 **확인 구간의 실제 순위가 없다는 사실**을 판단 불가의 주된 이유로 제시했다. 미래값을 숨긴 것은 실험 설계상 의도된 조건이다. 이 부재를 지적하는 문장 자체는 사실 오류가 아니고, HOLD도 허용된 출력이다. 다만 이번 출력에서는 주어진 과거 흐름으로 미래를 예측하기보다, 미래 관측을 받은 뒤 지속성을 확인하려는 응답 양상이 나타났다. 이를 기술 실패나 정답 예측으로 바꾸지 않고 그대로 보류로 유지해야 한다.

상품 **2816996·3450561·4205649의 `unknowns[0]`**는 확인 구간을 `2026-10-13~2026-10-19`라고 구체화했다. 입력이 정의한 것은 이후 **7개 관측일**이며 미래 수집 일정은 제공되지 않았다. 따라서 연속된 7개 달력 날짜로 확정한 범위는 입력에서 보장되지 않는 가정이다. 이 세 항목은 자동 수치 플래그에 잡히지 않았으며, 근거 배열 밖에 있어 위 1/6에는 더하지 않았다.
