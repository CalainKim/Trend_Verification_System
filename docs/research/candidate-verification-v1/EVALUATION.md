# 후보 조사와 판단 논리의 평가 명세

2026-11-12 · `candidate-verification-v1` · 새 실제 평가 결과 없음

## 무엇을 비교하는가

새 후보 6건에 대해 **Claude/Qwen × 인터뷰 가설 제공/미제공**을 교차한다. 계획된 최종 출력은 24건이며 단계별 호출 수를 뜻하지 않는다. 모델 내 인터뷰 유무 차이를 먼저 비교하고 모델 간 공통·상이한 오류 유형을 보조적으로 정리한다. 같은 자료집·초기 근거·검색기·검색 한도·조사 흐름·반증 단계·모델 내 설정을 사용한다.

인터뷰 미제공 조건에는 모든 단계에서 가설 내용·ID·적용 양식·앞 조건의 출력이 없어야 한다. 자료집에는 인터뷰 자료와 평가 라벨을 넣지 않는다. 두 조건이 같은 자료집을 탐색하더라도 질의와 획득 근거가 다를 수 있어, 측정하는 것은 인터뷰 가설로 안내한 **조사와 판정 전체의 차이**다.

별도 반증은 두 조건에 공통이다. 초기/최종 판정의 변화는 절차 진단이며 반증 유무의 인과 비교가 아니다. 미래 반응, 인터뷰에 대한 동의, 사람의 최종 선택을 유행 정답으로 쓰지 않는다.

## 평가 자료를 만드는 순서

1. **모집 규칙 고정:** 새 후보 선정·제외 규칙, 대상·판단 시점, 초기 트리거를 기록한다. 기존 성공 사례나 결과를 알고 선정한 스타일을 본 평가로 재사용하지 않는다.
2. **가설·자료집 동결:** 인터뷰 해석을 사람 검토하고 후보별 자료집의 범위·시점·출처·재게시를 확인한다. 버전과 해시를 남긴다.
3. **출력 전 기준표:** 응도와 도은이 전체 자료집에서 확인 가능한 사실·중요 반대 근거·미확인 정보를 각각 적는다. 중요한 반대 근거는 무시하면 판정이나 주요 이유가 달라질 수 있는 내용이다.
4. **기준표 합의:** 최초 표를 보존하고 별도 합의본을 고정한다. 미해결 항목은 강제 정답으로 쓰지 않는다. 모델 출력은 아직 보지 않는다.
5. **실행과 가림:** 계획된 순서로 실행 기록을 저장한다. 모델·조건·호출 순서·가설 적용표를 숨긴 공통 최종 출력에 임의 ID를 부여한다. 이유의 문장을 임의로 고쳐 가리지 않는다.
6. **독립 판독:** 두 평가자가 각각 모든 사실 주장, 논리 연결, 반대 근거 처리, 판정·보류를 평가한다. 원문을 읽을 수 있는 기술 실패는 진단하되 정상 판정으로 승격하지 않는다.
7. **최초 일치와 합의:** 최초 값을 확정하고 나서 비교한다. 불일치·수정 사유·미해결을 보존한 별도 합의본을 만든다.
8. **조사 경로 진단:** 주평가 확정 뒤 검색·반증·가설 적용 기록을 열어 누락과 수정 이유를 설명한다. 주평가를 유리하게 다시 쓰지 않는다.

가설 적용표를 가려도 본문의 표현에서 조건을 추측할 수 있다. 평가자가 추측했는지와 이유를 기록하며 완전한 블라인드라고 단정하지 않는다.

## 판독 기준

| 항목 | 기준과 선택지 |
|---|---|
| 사실 주장 지원 | `supported / unsupported / contradicted / unverifiable / not_reviewed`. summary·수정 이유 등 모든 문장의 사실 주장을 원자적으로 분리하고 반복은 한 번만 센다. 모델이 실제 제공받은 근거가 해당 주장을 뒷받침해야 한다. |
| 논리적 연결 | `coherent / invalid / unresolved / not_assessable`. 공개된 전제→해석→판정의 연결, 근거 없는 도약, 자기모순, 순환논증, 중요 반대 근거의 영향 누락, 대상·시점 범위 이동을 확인한다. |
| 중요 반대 근거 | 합의 기준표의 항목별 `addressed / missed / misrepresented / not_reviewed`. 이름만 언급하면 반영으로 보지 않는다. 사실과 판정에 미친 영향을 정확히 다뤄야 한다. |
| 중대한 오류 | 수치·단위·기간·대상 혼동, 없는 사실, 지지되지 않는 인과·구매 단정 등 판정 또는 주요 이유를 바꾸는 오류. 원문 위치·근거·영향을 기록한다. |
| 판정 적절성 | `appropriate / inappropriate / unresolved / not_assessable`. 평가자의 선호와 같아야 하는 것이 아니라 제시한 근거·반대 설명·불확실성에 맞아야 한다. |
| HOLD 적절성 | 구체적인 핵심 정보 부족·충돌과 확인 조건이 있는지 확인한다. 미래값 부재만 이유라면 부적절하다. HOLD가 아니면 해당 없음이다. |
| 가설 적용 진단 | 제공 조건에서만 근거 연결, 해당 없음/자료 부족의 이유, 미검토 가설의 사실화 여부를 점검한다. 미제공 조건을 가설 미언급 때문에 감점하지 않는다. |

`coherent`는 표시한 전제와 제한 안에서 판단 이유가 연결되는 경우다. `invalid`는 판정에 영향을 주는 도약·모순을 특정한 경우, `unresolved`는 판독했지만 평가를 확정하지 못한 경우, `not_assessable`은 원문 부재·읽을 수 없는 잘림 등으로 판독 불가능한 경우다. 미작성 null은 미평가다. 사실 인용이 맞아도 결론으로의 연결이 부적절할 수 있고, 논리 구조가 일관되어도 전제 사실이 틀릴 수 있으므로 둘을 별도로 판독한다. 내부 사고 과정을 추정해 채우지 않는다.

## 수치와 분모

각 모델×조건의 계획 수·실제 첫 시도 수·미실행 수를 공개한다. `N`은 계획된 사례 중 첫 실행을 실제 시도한 사례 수다. 재시도는 독립 사례가 아니며 첫 실패를 덮어쓰지 않는다. 실행 폴더 생성 전 입력·설정 거부는 미실행 사유로 따로 기록하고 N에 넣지 않는다. 합성 예제·과거 기록은 N에서 제외한다.

| 지표 | 분자·분모와 함께 보고할 항목 |
|---|---|
| 주장 근거 충실도 | supported ÷ 판독 완료한 사실 주장. unsupported·contradicted·unverifiable도 분모에 포함. 전체 사실 주장 수·해석 수·미판독 수 병기 |
| 논리적 타당성 | coherent ÷ (coherent + invalid). unresolved·not_assessable·미평가 건수와 평가 확정 수/N 병기 |
| 중요 반대 근거 반영률 | addressed ÷ 합의 기준표의 평가 가능한 중요 반대 근거. 자료집 전체를 기준으로 하며 아직 판독하지 않은 항목이 있으면 미완료 표시 |
| 중대한 오류 발생 | 오류 확정 사례 E ÷ N. 오류 유무 미확정 U가 있으면 최소 확인 비율과 가능한 범위 [E/N, (E+U)/N], U를 함께 표시 |
| 판정 적절성 | appropriate / inappropriate / unresolved / not_assessable / 미평가 건수. 적절 비율은 appropriate ÷ (appropriate + inappropriate), 평가 확정 수/N 병기 |
| 보류 적절성 | HOLD의 위 범주별 건수와 사유. HOLD가 없으면 해당 없음 |
| 전체 처리 | 유효 CONFIRM / HOLD / REJECT, api_error / schema_error 건수와 각 수/N. 미실행은 별도 |
| 합의 전 평가자 일치 | 동일 항목에 대해 두 평가자가 확정한 비교 가능한 값 중 같은 값의 비율. 항목 종류별 분모·제외 사유와 판정 적절성 교차표 |

분모가 없으면 해당 없음, 아직 시도·판독하지 않았으면 미측정/미완료다. 기술 실패를 오류 없음이나 정상 HOLD로 바꾸지 않는다. 읽을 수 있는 실패 원문 진단은 별도 표로 보존한다.

**반대 근거의 누락은 경로를 구분한다.** 전체 자료집의 중요한 반대 근거를 못 찾았다면 조사 누락이다. 실제 전달됐는데 설명에 반영되지 않았다면 해석 누락이다. 전체 반영률을 주로 보고, 획득한 반대 근거에 한정한 반영은 분모를 밝힌 보조 진단으로만 둔다. 후자만 보고 조사의 실패를 숨기지 않는다.

## 비교 결과를 해석하는 방법

같은 후보에서 인터뷰 유무에 따른 근거 오류·논리 오류·반대 근거·판정·실패 변화를 짝지어 낸다. 근거가 늘면서 오류도 늘거나, 보류를 늘려 답한 부분만 좋아진 경우를 함께 설명한다. 적은 주장만 해서 지원 비율이 높아지는 현상도 주장 수와 함께 본다.

후보 6건의 예비 설계로 통계적으로 확실한 우위, 시장 일반화, 시간 일반화를 주장하지 않는다. 합격선·가중 종합 점수·모델 우승을 만들지 않는다. 사람 합의는 제공 자료에 대한 검토 결과이며 미래 유행의 정답이 아니다.

## 필수 구현 검사

| 검사 | 필요한 동작 |
|---|---|
| 미래 발표·관측·가용 자료 | 현재 입력에서 제외 또는 입력 오류로 기록 |
| 재게시와 같은 출처의 반대 관측 | 재게시로 독립 근거를 늘리지 않고 새로운 반대 관측은 보존 |
| 인터뷰 미제공 조건 | 모든 단계 요청에 가설·ID·적용 양식·다른 조건 이력 없음 |
| 검색 범위 | 동결 자료집만 탐색, 검색 횟수·반환 한도 준수, 의무 반대 검색 수행 |
| 반증 분리 | 조사와 별도 요청 문맥의 반증 기록 존재 |
| 인용 | 최종 출력은 실제 전달된 자료 ID만 인용; 잘못된 ID·형식은 기술 실패 |
| 미검토 가설 | 확정 기준으로 적용하지 않고 진단용 가설로 표시 |
| 미래값 없음 | 그 이유만으로 HOLD를 정당화하지 않음 |
| 반대 근거 추가 | 의미 판독에서 그 영향 설명 확인; 무조건 판정 반전을 요구하지 않음 |
| 참인 전제·틀린 연결 | 사실 지원과 논리 오류를 별개로 기록 |
| 사람 최종 결정 | AI 제안과 분리하여 사람 변경 이유·근거 보존 |

검사 통과는 실행 계약의 검증이며 실제 모델의 의미상 품질 결과가 아니다. [양식 안내](forms/README.md)와 [구현 상태](IMPLEMENTATION.md)를 함께 본다.
