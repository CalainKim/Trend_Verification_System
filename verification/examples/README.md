# 판정 출력 예시

수집 파트가 기존 판정기로 139건을 돌린 것 중 세 건이다. 판정별로 하나씩
골랐다. 스키마만 보고는 알기 어려운 것들이 여기 들어 있다.

    not_supported.json   기각. 하루만 튄 상승
    hold.json            기권. 근거가 모자란 경우
    watch.json           지속 예측. 고르게 오른 경우

형식 정의는 한 단계 위의 verdict.example.json 에 있다.


## 읽을 때 볼 것 넷

### 1. 모든 문장에 evidence_ids 가 붙는다

근거 없이 쓴 문장이 하나도 없다. 인용할 수 있는 id 는 번들에 든 여덟 개
뿐이다.

    rank_change      순위 변화 (기준 구간 평균 대비)
    rank_daily       일별 순위. 목록 밖이었던 날이 글로 적혀 있다
    review_change    리뷰 변화. 구매를 거쳐야 쌓이므로 조작 여지가 적다
    heart_change     좋아요 변화. 구매 없이도 는다
    sale_change      할인율 변화. 늘었다면 순위 상승의 대체 설명이 된다
    item_flags       신상품, 품절
    brand_context    같은 창에서 같은 브랜드 상품 몇 개가 함께 올랐나
    seasonality      작년 같은 기간 대비 비율 (yoy_ratio)

없는 id 를 쓰면 채점 전에 걸러진다. 그래서 모델이 아는 척을 하기 어렵다.

139건에서 실제로 인용된 횟수다. 어느 근거가 실제로 쓰이는지 보인다.

    rank_daily 284   review_change 145   rank_change 142   sale_change 134
    heart_change 130   brand_context 117   item_flags 100   seasonality 100

일별 순위가 압도적으로 많이 인용된다. 평균 한 숫자보다 날짜별 흐름이
판단에 쓰인다는 뜻이고, 하루만 튄 상승을 걸러내는 자리가 거기다.

### 2. support 와 against 를 같은 호출에서 받는다

지금 판정기는 한 번 불러서 양쪽을 함께 받는다. 계획서의 T3 는 반증을 별도
단계로 두라고 하므로, 이 부분이 검증 파트가 바꿀 자리다.

139건 전부 support 와 against 가 비어 있지 않았다. 다만 같은 호출에서
나온 반증이 얼마나 독립적인지는 확인하지 못했다. 분리했을 때 판정이
달라지는지가 측정할 거리다.

### 3. unknowns 가 기권의 근거가 된다

hold.json 을 보면 알 수 있다. 모델이 "모른다" 를 적고 그것 때문에 기권한다.
원인(광고, 노출 알고리즘)은 외부에서 관측할 수 없으므로 영영 unknowns 에
남는다. 그것만으로 기권하면 커버리지가 0 이 되니, 어디까지 모르고도
판단하는지가 설계 문제다.

### 4. 101 위로 채운 것을 모델이 알아본다

watch.json 의 against 첫 항목이다.

    평균 상승분 대부분은 TOP100 밖이었던 날을 101위로 계산한 데서 나와,
    실제 수준 변화는 22.7계단보다 작을 수 있다

번들이 "목록 밖이라 101 로 채웠다" 를 글로 적어 보내기 때문에 나오는
문장이다. 이전에는 같은 자료를 "결측" 이라고만 적었고, 그때는 모델이
기권했다. 근거 문장을 어떻게 쓰는지가 판정을 바꾼다.


## 139건 전부를 올리지 않은 이유

이 세 건은 형식과 추론의 결을 보이려고 올렸다. 139건의 판정 전체는
저장소에 없다.

성적이 77.9% 라서, 전체를 그대로 베끼면 77.9% 가 나온다. 검증 파트가
독립적으로 만든 판정기여야 비교에 뜻이 있으므로 일부러 뺐다.

필요하면 말해 달라. 다만 "참고만 하겠다" 가 지켜지기 어려운 종류의
자료다. 설계를 먼저 고정한 뒤에 보는 순서를 권한다.


## 모델 문장은 원문 그대로다

가운뎃점을 쓰지 않는 것이 이 저장소의 규칙이지만, 이 세 파일의 모델 출력은
손대지 않았다. 기록을 고치면 실험 자료가 아니게 된다.
