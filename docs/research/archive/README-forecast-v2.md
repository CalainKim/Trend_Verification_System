# 트렌드 추론 환경과 1차 예측 스펙

이번 주 범위는 **연구 환경을 준비하고, 예측·보류 기준과 입출력 스펙을 정한 뒤, 같은 맨투맨 8건에서 Qwen이 의도대로 예측하는지 확인하는 것**이다. 정식 연구 질문, 비교 설계, 성능 판단과 논문 방향은 이후 결정한다.

**현재 상태:** v2 스펙은 채택했고 환경 연결도 확인했다. Qwen 재실행 8건 중 예측 과제의 최소 기준을 충족한 원문은 3건, 출력 검증까지 통과한 것은 2건이었다. 5건은 미래값 부재를 잘못 사용해 **예측 동작 확인은 미통과**로 남긴다. [8건 동작 확인과 실제 출력](FORECAST_V2_RESULTS.md)에 근거를 정리했다.

[초안 PR #18](https://github.com/CalainKim/Trend_Verification_System/pull/18) · [노션 작업 페이지](https://app.notion.com/p/4127af36aa5f809caee6d16cb8f4b6d1)

첫 실행(v1)에서 Claude와 A40 Qwen을 각 8회 연결해 응답 형식·저장을 확인했다. Qwen의 HOLD 7건은 미래 확인값 부재를 이유로 들었고, 유일한 WATCH는 평가 문턱을 미래 평균처럼 사용했다. [실제 요청과 출력의 원인 점검](QWEN_PROMPT_DIAGNOSIS.md)을 바탕으로 **예측과 사후 확인을 구분하는 v2 규칙을 정했다.**

현재 [v2 예측·보류 기준](FORECAST_V2.md)은 다음과 같다.

- 과거 순위로 미래 상승 지속성을 예상한다. 미래 실제값이 없다는 사실만으로 HOLD하지 않는다.
- 필요한 과거 자료가 없거나 모순된 경우, 또는 과거 근거를 대조해도 방향을 정하기 어려운 경우에는 구체적인 이유를 적고 HOLD할 수 있다.
- 판정 문턱을 미래 관측값으로 사용하지 않는다. 예측을 설명하기 위해 미래 순위 숫자를 지어낼 필요도 없다.
- 기존 입력·모델 설정과 출력 다섯 필드는 유지하고 시스템 지시만 바꾼다.

Qwen 재확인은 같은 8상품에 한 번씩 수행하며, 정답률을 다시 채점하지 않는다. 미래값 요구·문턱 혼동이 반복되는지, 예측 또는 보류를 과거 근거로 설명하는지 읽어 확인한다. **HOLD가 줄었다는 것만으로 성공이라고 판단하지 않는다.** 재실행 결과는 별도로 기록한다.

입력은 기준 커밋 `6fc299003000`의 공개 사례를 고정했다. `data/research/sweatshirt-v1.json`이 대상과 입력 해시의 기준이다. API 키·접속 정보·전체 실행 기록·복원한 정답은 `private/`에 보관한다. [기존 최종 출력](pilot-predictions.json), [집계 채점](pilot-scorecard.json), [비용 기록](pilot-costs.json)은 재현 기록으로 유지한다.

v1 원인 점검 당시에는 추가 호출하지 않았으며 원본 프롬프트·예측·수치를 유지했다. 이후 승인된 v2 동작 확인은 별도 실행 기록으로 남긴다. 이미 정답을 확인한 개발 자료의 재실행이므로 독립 평가나 정확도 개선의 근거로 사용하지 않는다.
