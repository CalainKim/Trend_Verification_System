## 동일하게 유지한 절차

두 모델에 같은 후보·초기 근거·동결 자료집을 사용하고, 각 모델의 설정은 인터뷰 제공 여부에 따라 바꾸지 않는다. 초기 제안 → 자료집 검색 계획과 검색 → 별도 반증 → 최종 제안 순서다. 검색은 최대 두 번, 질의마다 상위 세 문서까지이며 반대 근거 목적의 검색이 필요하다. 검색 기록의 전체 문서를 프롬프트에 중복 복사하지 않고 실제 제공 근거 목록에 한 번 담는다.

최초 네 조건의 라이브 프롬프트 버전은 `candidate-investigation-v1-live1`이다. `without_interview`에는 모든 단계에서 가설 내용·ID·적용 양식·다른 조건의 답을 전송하지 않는다. 가설과 인터뷰 원문은 검색 대상에서도 제외한다. 검증기는 `with_interview`의 미검토 가설을 확정 기준처럼 `applied`로 표시한 출력을 거부한다.

## 계약 설명을 명료하게 한 별도 개발 진단

최초 네 조건을 저장한 뒤 `candidate-investigation-v1-live2`를 준비했다. 응답의 필수 최상위 키와 제공 조건의 모든 가설 ID를 명시하고, 미검토 가설의 `applied` 선택을 직접 금지했다. 자료 부재와 실제 반대 관측을 구분하도록 설명도 보강했다. 쇼핑 클릭을 검색량·구매량으로 바꾸지 않도록 측정 이름을 유지하는 지시를 명료하게 했다. 이는 원출력의 구조 누락과 설명 모호함을 본 뒤 한 개발 수정이다.

Qwen 제공 조건의 실패 기록을 부모로 삼는 **수동 진단 한 번**을 별도로 실행했다. 최초 승인·호출 한도·누적 비용·GPU 종료 기한을 바꾸지 않고, 전체 흐름에 필요한 호출 여유를 검사한 뒤 시작했다. `diagnostic_authorized` 이벤트에 부모 run ID·기록 해시·새 프롬프트 버전·이유를 추가했다. 자동 재시도가 아니며 최초 네 조건의 기록을 대체하지 않는다.

추가 진단 run ID는 `cv1-12d002c78cae4b67aed9fdc5d524c35f`다. 최상위 필수 키와 H1~H10 행은 모두 반환됐지만 초기 제안 단계에서 다시 `schema_error`가 발생했다. 반대 주장에 빈 인용 목록을 사용했고 모든 가설 행에서 `supporting_evidence_ids`를 빠뜨렸으며, 미검토 H1을 `applied`로 표시했다. 유효 최종 제안은 없다. 해당 원응답과 검증 실패도 보존하고 더 호출하지 않았다.

필수 항목 설명을 명료하게 하는 것만으로 중첩 출력 계약을 충족하지 못했다. 본 평가에 앞서 제공자가 지원하는 구조 강제 출력의 적용 가능성을 확인하고, 가설별 중첩 결과를 분리해 생성·검사하는 방식 등을 구현·시험해야 한다. 이는 **다음 구현 과제이며 현재 구현됐다는 뜻이 아니다.** 실제 전송과 실패 차단은 확인했지만, 인터뷰 가설을 포함한 전체 절차를 연구에 바로 쓸 준비가 끝났다고 판단하지 않는다.

이 진단에서 출력이 개선되더라도 다른 모델·미제공 조건과 같은 프롬프트에서 수행한 통제 비교가 아니다. 수정 효과나 인터뷰 효과의 논문 결과로 집계하지 않는다.

## 실행과 기록 확인

라이브 실행기는 [live.py](../../../src/trend_verification_v1/live.py)에 있다. 별도로 고정한 승인 기록이 후보·자료집·가설·설정·이전 비용 장부의 해시를 묶는다. 각 호출 전에 누적 예산을 예약하고 사용량을 알 수 없으면 예약을 유지한다. 기존 비용 장부를 초기화하지 않으며 이 점검의 정상 반복·자동 재시도는 허용하지 않는다. 비용과 임대 운영 기록은 연구 결과에서 분리한다.

이번 GPU 연결에서는 제한된 키로 자동 종료 경로를 확인하지 못했다. 이를 자동 종료가 준비됐다고 표시하지 않는다. 실제 콘솔을 지켜보며 종료하는 모드는 대상 Pod·같은 절대 종료 시각·최근 확인 시각을 별도로 기록하고, 확인 기록이 만료되면 다음 모델 호출을 차단한다. 요청 종료 여유와 기존 임대 기한은 그대로 적용한다. 이 호출 차단은 GPU 자체의 자동 종료를 뜻하지 않으며, 실제 중지 확인을 별도로 남겨야 한다.

점검 후 Runpod 콘솔의 `Not running` 상태와 시작 버튼을 확인해 2026-11-12 11:14:20 UTC에 종료 확인을 기록했다. 임대 시간을 원래 시작 시각부터 정산했고, 로컬 SSH 터널도 종료했다. 원출력은 로컬에 보존했다.

```powershell
# 기존 예산 장부 읽기만 수행한다.
python scripts/run_candidate_verification.py budget-audit

# 저장된 실행과 입력·요청·응답 해시를 확인한다.
python scripts/run_candidate_verification.py verify private/candidate-live/runs/<run_id>

# 저장 결과를 읽는 화면을 만든다. 모델을 다시 호출하지 않는다.
python scripts/build_candidate_report.py --runs-dir private/candidate-live/runs --output-dir private/candidate-live-report
python scripts/serve_candidate_report.py --report-dir private/candidate-live-report --port 8775
```

라이브 호출은 준비한 승인·입력 파일을 지정한 `live` 명령으로만 수행한다. `demo`는 계속 합성 응답을 사용하며 실제 API 결과가 아니다. `synthetic`은 자료의 출처, `demo`와 `execution_kind`는 실행 방식이므로 서로 구분한다. `budget_blocked`, `api_error`, `schema_error`와 최종 판정 없는 기록을 HOLD로 바꾸지 않는다.

새 실제 후보 선정, 사람의 인터뷰 해석 검토, 출력 전 기준표 작성, 가림 독립 평가와 논문 본 비교는 남아 있다. 기존 맨투맨 8상품의 원출력·평가·봉인 해시는 보존하고 이번 기록이나 본 평가에 합산하지 않는다.
