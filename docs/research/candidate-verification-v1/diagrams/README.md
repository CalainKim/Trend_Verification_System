# 후보 검증 구조도

`candidate-verification-v1`의 방법론과 논리 검증 설계다. 그림은 데모에서 확인할 흐름을 설명하며, 실제 사례에서 방법의 효과가 측정되었다는 의미는 아니다.

| 파일 | 용도 |
|---|---|
| `candidate-verification-v1.drawio` | draw.io에서 직접 편집하는 두 페이지 원본 |
| `candidate-architecture.svg` / `.png` | 초기 신호, 근거 검토, 추가 질문, 반증, 판정 수정, 사람 판단의 구조 |
| `candidate-evaluation.svg` / `.png` | 인터뷰 가설 제공 여부의 비교와 독립적인 사람 평가 설계 |
| `generate_diagrams.py` | 동일 좌표와 문구로 원본·미리보기 생성 |

## 구조도 읽기

시계열은 초기 후보를 찾는 신호이면서 이후 판단에 사용하는 실질적인 근거다. 후보의 정의·대상·판단 시점과 근거 묶음을 고정한 다음, 검수된 인터뷰 가설을 사용해 잠정 판단을 만든다. AI는 판단을 바꿀 추가 질문을 고르고 고정된 자료 안에서 검색한다. 별도 반증 검토를 거쳐 `CONFIRM / HOLD / REJECT` 권고와 수정 이유를 기록하고, 사람이 최종 판단을 남긴다.

후속 관측은 새 판단 시점에 등록한다. 이전 근거와 판단을 보존하고 새 기록을 추가하는 순환 구조다. AI의 권고를 시장의 정답으로 해석하지 않는다.

## 평가도 읽기

Claude와 Qwen 각각에 대해 인터뷰 가설 제공·미제공 조건을 비교한다. 후보·초기 근거·추가 검색 자료 묶음·검증 절차는 같게 두고, 모델 내 실행 조건과 출력 형식도 유지한다. 실제로 선택된 질문과 검색 결과는 함께 기록한다.

두 평가자는 모델 출력을 보기 전에 사실·반대 근거·미확인 정보의 기준표를 만든다. 이후 모델명과 조건을 가린 출력을 독립적으로 검토하고 최초 평가와 합의 결과를 따로 보존한다. 검토 대상은 사실과 출처의 일치, 반대 근거 반영, 추가 질문의 필요성, 판정 수정의 논리다. 표본 수·수치 설정·측정 결과는 이 설계도에 확정하지 않는다.

## 편집과 재생성

draw.io에서 `.drawio` 파일을 열면 도형·문구·연결선을 각각 편집할 수 있다. 저장소의 재생성 기준은 `generate_diagrams.py`이므로 그림 내용 변경 시 생성기도 같이 수정한다.

```powershell
python -X utf8 docs/research/candidate-verification-v1/diagrams/generate_diagrams.py
```

Python의 Pillow와 한국어 글꼴을 사용한다. Windows에서는 맑은 고딕을 우선 사용한다. PNG는 글꼴이 포함된 미리보기이며, SVG와 draw.io는 열람 환경의 한국어 글꼴에 영향을 받을 수 있다. PNG/SVG는 원본과 같은 좌표에서 생성한 미리보기이고 draw.io 애플리케이션의 직접 내보내기 결과는 아니다.

생성기는 문구 너비와 페이지 경계를 검사한다. 생성 후 두 PNG를 열어 연결선, 글자 잘림, 요소 겹침을 확인한다.
