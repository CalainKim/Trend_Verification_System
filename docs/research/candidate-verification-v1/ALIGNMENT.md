# 원래 취지와 현재 구현 범위의 대조

2026-11-12 · `candidate-verification-v1`

## 이번 결정

초기 목표는 관심이 변한 후보를 **확정하거나 기각할 수 있도록 근거를 조사하고 반증하는 검증 시스템**이었다. 따라서 관찰 우선순위 카드에서 멈추었던 `evidence-priority-v1`을 현재 과제로 사용하지 않는다. 새 과제는 초기 시계열 신호 → 인터뷰 검토 가설·당시 맥락 → AI 주도 조사 → 별도 반증 → 확정·보류·기각 제안 → 사람의 최종 판단으로 이어진다.

이 결정은 원래 제품 목표에 가까운 검증 절차를 구현하는 것이다. 그 자체로 시장 유행을 정확히 예측하거나 기업의 의사결정을 개선했다는 결론은 아니다. 연구의 주된 검증 대상은 외부에서 확인 가능한 **출력의 근거 충실성과 논리적 타당성**이다.

## 대조한 자료

| 자료 | 확인된 취지 | 이번 반영 |
|---|---|---|
| 사용자 제공 원래 작업 대화의 최초 요청(비공개) | 후보를 확정하거나 기각하는 검증 시스템이라는 원래 과제 | AI는 조사와 판정 제안을 맡고 사람이 최종 결정 |
| [최초 인수인계](https://github.com/CalainKim/Trend_Verification_System/blob/39705408a432eba670fe7002bbe1e3e3391e21df/docs/verification-handoff.md#L81) | 절차의 투명성과 반증 가능성을 중시 | 조사·인용·반증·수정 기록 보존 |
| [확인한 GitHub 인수인계](https://github.com/CalainKim/Trend_Verification_System/blob/8886fa181f314a001b090cdbb24752dd89aedc0b/docs/verification-handoff.md#L468) | 판정값뿐 아니라 근거와 반증 시도가 중요 | 사실 근거와 논리적 연결을 별도 평가 |
| [T2·T3](https://github.com/CalainKim/Trend_Verification_System/blob/8886fa181f314a001b090cdbb24752dd89aedc0b/docs/verification-handoff.md#L495) | 최종 확정 판단을 모델에 위임하지 않고, 수집과 분리된 반증 단계 마련 | 조사와 별도 요청 문맥의 반증 단계, 사람 최종 기록 |
| 사용자가 제공한 실제 전사문 | 대상 집단, 관심과 구매의 차이, 홍보·노출, 계절성, 착용 수용성에 관한 탐색적 논의 | 사람 검토 전 가설로 추출. 사실·기업 요구사항·모집단 통계로 승격하지 않음 |

원래 작업 대화의 정확한 전체 식별자와 최초 사용자 턴은 비공개 작업 기록에서 확인한다. 공개 초안에는 접근 가능한 GitHub 근거와 아래 해석 경계를 함께 둔다. 전사문의 표현을 책임자나 기업 담당자의 정확한 발언처럼 인용하지 않는다.

## 이전 설계와의 차이

| 구분 | 보존하는 이전 기록 | 현재 과제 |
|---|---|---|
| 판단 목적 | `evidence-priority-v1`의 관찰 우선순위 | 현재 후보 가설의 확정·보류·기각 제안 |
| AI 역할 | 주어진 동일 묶음에서 기본/구조적 판정 비교 | 동일한 동결 자료집 안에서 질문·추가 근거를 선택하는 조사 |
| 반증 | 단일 판정 안의 반대 설명 검토 | 조사 후 별도 요청으로 반증 검토 |
| 실험 요인 | 기본 판정과 구조적 검토 | 동일 조사 절차에서 인터뷰 가설 제공 유무 |
| 최종 결정 | 사람 검토를 전제로 한 카드 | 모델 제안과 별도로 사람이 최종 결정·수정 이유 기록 |
| 정답 | 과거 상품 순위 실험은 지속성 정답 사용 | 사실·반증 기준표와 출력 논리의 사람 판독; 미래 유행 정답 없음 |

초기 시계열 신호는 후보를 올리는 출발점이다. 인터뷰 가설이 신호를 대신하거나 모든 후보에 동일한 결론을 주지 않는다. 당시 자료와 연결되지 않는 인터뷰 가설은 `not_applicable` 또는 `insufficient_evidence`로 남긴다. 인터뷰의 민감하거나 불명확한 발화를 논문에 그대로 공개하지 않는다.

## 구현과 연구 완료의 경계

범위에 맞는 독립 실행 경로와 합성 예제를 만들고 평가 계약을 준비했다. 사용자 요청으로 기존 링거티 실제 관측을 활용한 [모델 동작 점검](LIVE_CHECK.md)을 추가로 실행했고, 인터뷰 제공 조건의 중첩 출력 계약 보완이 필요함을 확인했다. 새로운 실제 후보 수집, 가설 검토자의 승인, Claude/Qwen 본 비교와 두 사람의 독립 평가는 후속 작업이다. 이전 상품 출력·합성 결과·이번 개발 사례의 동작 점검을 본 평가에 합산하지 않는다.
